# M6 浏览器新凭证的扫描材料计划

状态：独立 helper 和执行入口已完成，54 项离线测试通过；实际扫描材料查看尚未执行。浏览器续验通过后，另行开放一个独立的扫描材料窗口。当前冻结的续验脚本不增加动作。

入口为 `tests/security/capture-m6-browser-key.mjs`，需要独立的 `M6_BROWSER_KEY_SCAN_READY=true` 门禁。离线证据见 `artifacts/M6/browser-key-scan-final-focused-unit.json` 与 `browser-key-scan-independent-source-gate.json`。导出 SQL 已通过独立 PostgreSQL 16.15 的 12/12 验证，证据为 `artifacts/M6/browser-key-scan-postgres-2026-10-11T04-18-17-139Z.json`；使用真实非 owner 数据库角色、编译器、计划持久化和授权激活，网关 ACK/GET 明确为合成证据。该验证不代替当前网关、浏览器或实际凭证查看验收，原 `PG_PENDING` 交接记录保留。

目的：浏览器通过真实审批工作流生成的新 API Key 尚未被临时查看，遮蔽列表不能证明最终泄露扫描已覆盖这份 Key。此窗口只查看该新凭证一次，不创建、轮换或吊销凭证，不重复查看既有 B 凭证。

执行前只读核验以下完整绑定：

- 当前私有引用中的 `browserWorkflowId`、新应用 ID、原开发者 ID、C3 集群 ID、工作区 ID。
- 原执行键对应的工作流回执确已成功，三步原生创建均有完整成功回执。
- 新 grant、第一代 credential、Consumer、ACL、原生 Key 的类型、父关系和 ID 与不可变计划一致；两份活动凭证引用存在。
- 浏览器保存的最新具名 Portal cookie jar 仍属于原开发者、原会话和原租户，CSRF 与当前服务器会话一致。若会话已失效，停止；不自行重新登录、刷新或更换身份。

核验通过后，将唯一查看请求的原键、精确路径、租户、开发者、凭证 ID 和修订号预先写入现有 0600 私有引用，再通过 Portal BFF 发出一次授权查看 POST。成功状态接受实际 Nest 2xx（包含 201）；响应 Key 仅在进程内存和同一私有引用的扫描材料中保存，不截图，不输出原始响应、cookie、CSRF、Key 或 SQL 行。

公开证据只记录绑定核验布尔、查看状态、服务器 request ID、审计匹配、无原生变更和材料已保存布尔。该查看请求作为一次产品写入计入实际审计总数。未知响应、绑定变化、拒绝或解析失败立即停止，保留原请求记录，不自动重发。

最终扫描必须包括此新 Key、浏览器刷新后的会话材料、原有全部凭证和四用途监控材料，并覆盖后续手工截图、源码、编译输出及压缩报告。只有全部证据完成且扫描通过后才移除私有引用。
