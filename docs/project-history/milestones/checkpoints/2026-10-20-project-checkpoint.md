## 3. 本轮技术方案与决策依据

1. **保持 Kong 1.5 白名单与 BFF 边界。** 插件 schema 使用 `/plugins/schema/{name}`；企业能力由平台实现，不能为通过验收新增不存在的 Kong 端点。
2. **辅助只读按原封存对象收窄。** Portal credential 的 Consumer 父对象检查及最终激活读取，使用指定对象的 Validation 只读通道；保留当前主体、权限、工作区、原 SQL 材料及执行上下文核验。辅助读取不能产生写许可；最终 Native 写前检查和原回执回读保持完整。
3. **保持执行安全限额。** 原 500 次 Kong 调用、100 页及 5 分钟 claim 不变；不缓存旧批准、不延长原授权、不手动重放旧业务写入。
4. **观测只记录有界计数。** 固定阶段、步骤号、调用/分页/记录/字节数用于定位；不输出请求正文和凭证，诊断记录失败不改变业务结果。
5. **修复测试时钟竞争，保留产品期限。** 固定 Date/单调时钟并在 SQL consume 后推进过期；不提高生产期限或测试超时。实际 EntityService 已接入完整源码夹具，但受控 SQL/网络/租约不能当真实生产证据。
6. **未知结果靠原回执与新核验处分。** SQL042 的目标是提供安全核验流程；不能盲目重发原 Native 写入或直接改 SQL 终态。迁移必须先 041 后 042，使用隔离恢复副本先验收。
7. **证据与发布版本一一对应。** 专项测试、历史全测、当前 CI、真实运行和浏览器分别记账；Git tree 一致可用于核对源字节，不能替代真实业务验收。
