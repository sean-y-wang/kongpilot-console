# M3 工作区与迁移边界

工作区元数据位于控制台数据库。Kong 1.5.1 拒绝包含冒号的物理标签，因此逻辑 `workspace:pay` 编码为 `kos-ws-pay`，普通业务标签由统一标签适配器处理。浏览器选择的是控制台工作区 UUID；后端校验其集群、状态与 revision，不信任客户端标签。

默认工作区包含未打标历史对象和仅带 `kos-ws-default` 的对象。未知、已删除或多个保留工作区标签的对象进入隔离待修复范围，不归入默认工作区。停用工作区仍可只读查看，不能写入；元数据删除与恢复使用 revision 条件更新，编码在保留期内不重用。索引仅保存脱敏配置，返回搜索结果前重新读取 Kong 并验证当前归属。

Target 与凭证按实际 Upstream / Consumer 继承归属。所有引用操作再次检查真实父对象、目标工作区与权限。一般表单不能修改保留标签，工作区迁移使用单独的预览、确认、执行和核验流程。备注、负责人及扩展元数据保存在控制台，不添加 Kong schema 不支持的字段。

## 迁移

预览按 `size` / `offset` 遍历对象闭包和相关引用，限制为 100 页、10,000 条记录或节点及 32 MiB。完整原生配置只进入带独立 AAD 的加密计划；公开预览只包含标识、名称、标签、引用冲突与预算。Consumer 的六类凭证集合在执行与核验前重新分页比较，集合变化会在网关写入前停止。

迁移的原生写入只 PATCH 标签，并回读验证除 tags / updated_at 以外的配置指纹。Consumer 凭证不会重新生成密钥或密码；Target 继承 Upstream，不新增历史记录或改变有效 Target ID。共享证书、SNI、Service、Route、Plugin、Consumer 和实际 Upstream 引用必须保持同区；预览可展示冲突，存在冲突时不执行。

执行使用集群变更锁、原操作幂等键和独立的逐对象持久化进度。每次网关写入验证整个受信锁链的所有权；续租失败、锁被替换或上下文关闭会阻止后续写入。计划哈希、有效期和二次确认在获取锁之后再次检查，数据库进度更新校验 operation ID，避免旧执行覆盖新执行。

Kong 不提供跨对象事务或 CAS。确定的部分失败保留成功步骤；结果不确定时不会自动重发。核验只 GET 原生状态，在事务中检查计划及回执，生成新的计划哈希和确认信息。部分计划的有效期重新延长 30 分钟；继续执行需要读取原回执、再次预览和输入目标名称，并使用新的幂等键。

## 边界

工作区限制控制台管理范围，无法改变 Kong 的共享名称空间、Consumer 身份空间和全局插件运行效果。绕开 BFF 的 Admin 写者仍可造成多对象竞争；生产网络必须限制 Admin 调用者，外部自动化纳入统一执行通道。历史回收站和审计归属不会随实体迁移修改。

浏览器持久化未知操作时仅保存账号、集群、工作区、幂等键、操作 ID、时间和状态，期限 24 小时，不保存配置或秘密。切换工作区、重载或登录另一账号不会把回执请求发到新的范围。迁移预览、只读核验及索引刷新不写网关配置；这些精确路径的响应丢失允许重新读取状态，原生执行仍保持未知结果锁定。

M3 的管理员范围检查不代替 M4 四维 RBAC；执行证据见同目录验证报告。
