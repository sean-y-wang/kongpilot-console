# M9 运维工具箱实施计划

状态：2026-10-12 获用户授权恢复 M9–M11 开发。M8 阶段验收及品牌优化已落盘；M9 正在实施，尚未验收。保持 M9→M10→M11 顺序，最后执行整个平台商用回归。

## 交付范围

提供 `/toolbox` 节点状态、缓存、路由调试、批量操作、本人草稿五个标签。所有请求经过 BFF，列表和结果绑定原账号、集群、工作区与当前权限版本。既有 Portal、监控受管对象及未知结果保护继续适用。

| 功能 | 实际数据与执行来源 | 验收重点 |
| --- | --- | --- |
| 节点状态 | Kong `GET /status` | 真实观察时间、不可用状态；不把整节点统计伪称为工作区统计 |
| 缓存 | 精确 key 的 `GET /cache/{key}`、`DELETE /cache/{key}` | 全节点权限、二次确认、直接或审批执行、真实审计和原键回执 |
| 路由调试 | 有界授权配置捕获、1.5 匹配器、实际代理探测 | 正则、优先级、多条件、完整性和插件选择；模拟与实测分开展示 |
| 批量操作 | 显式根对象和当前 before，既有配置执行或专用工作区迁移计划 | 标签、插件启停、迁移、回收站删除；逐对象结果，未知结果停止 |
| 草稿 | 控制台 PostgreSQL 的本人版本化编辑材料 | 按范围续编、CAS、软删除和恢复、凭证不进入浏览器持久存储 |

## 已决定的边界

1. 节点连接统计与无法证明归属的缓存只能由完整集群授权查看；工作区、tag_group、entity 授权不会获得整节点聚合数据。缓存默认只显示存在状态、类型、字节数和观察时间，原始值不进入公开报告或日志。
2. 不提供未经实际 1.5 端点证明的缓存 key 扫描，也不默认开放清空全部缓存。key 使用固定字符、长度及路径校验，客户端不能提交任意 Admin method/path。
3. 缓存失效是独立运维动作。Kong 1.5 无缓存写回端点，界面明确由 Kong 按需重建，不提供虚假的回滚或回收站恢复。配置实体删除继续先完整归档到回收站。
4. 审批模式的缓存失效必须有同一工作流引擎的固定原生操作计划和私有执行许可；不能借零原生写元数据处理器、普通 HTTP 字段或旧工单号发包。直接模式也保留限流、集群锁、before 指纹、审计和原键回执。
5. 批量仅接受 1–50 个显式、类型化根对象。先完成当前权限、依赖、before 与受管对象预检，再冻结计划；真正执行复用已有 Mutation、Recycle 与配置步骤事实，不建立第二套可冲突的成功记录。工作区迁移复用 M3 专用迁移边界。
6. 所有批量和删除操作要求输入当前对象或计划名称二次确认。未知结果不换键重试；原回执提供成功、失败、不确定和未执行对象，继续处理须重新生成剩余对象的计划。
7. 草稿归本人及原 CID/WID，接口不能修改 owner、权限、集群或工作区。草稿保存属于编辑材料操作，提交配置另生成正式变更计划，仍遵守集群执行模式。归档可恢复，不物理删除历史版本。
8. 默认不保存私钥、密码、Key、Authorization、Cookie、含凭证 URL。服务器确需加密秘密材料时，使用既有产物 DEK/AAD、独立秘密权限和过期策略；普通草稿 GET 不回显秘密。

## 路由匹配和真实探测

已只读核对运行中 Kong 1.5 镜像的 `kong/router.lua`，源码 SHA256 为 `316d010942e82d069f719e505b96c2c9cca41c4ea6d7a3aaff773b30d8000c43`。此读源操作没有发送 Admin HTTP、修改容器或网关配置，属于设计依据，不算路由验收。

实现依据实际 1.5 传统路由算法：匹配类别先按条件数量及类别位权排序；类别内再考虑精确 Host、Header 数量、正则路径、`regex_priority`、最长普通路径及 `created_at`。同字段多值的 OR 与不同字段的 AND 分别处理，Header 按实际源码规范化，支持 source/destination CIDR、端口及 SNI。并列、缺少上下文、未授权竞争对象、PCRE 不支持或预算不足必须显示不确定。

正则执行必须有独立进程或工作线程时间与资源预算，不在主线程运行用户可控回溯正则。运行时选择的匹配引擎需记录版本及与 Kong PCRE 的已知差异；不能因缺少依赖默默退回无限制 JavaScript RegExp。插件配置选择沿用 M2 的八层绑定优先级，插件执行顺序另按已验证的 handler priority 展示，二者不能混为一谈。

真实探测只连接已登记集群的固定 proxy origin。输入 Host/path 用于路由匹配，不成为连接目的地；拒绝重定向、任意内网目的地和 Admin 地址。默认仅提供显式确认的 GET/HEAD，使用当前对象权限、严格超时及响应字节上限，不自动重试业务请求。敏感 Header 仅临时内存使用并立即清空。

返回实际 HTTP 状态、有限安全 Header 与 BFF 观察的 connect/TTFB/total；可信响应若包含 Kong 延迟指标再单独标明来源。没有实际仪表支持时不编造内部阶段或每插件耗时。业务响应内容默认不回显，不能把网关管理权限自动当作业务数据访问权限。

## SQL012 与目录

SQL012 增量增加本人草稿根记录和不可变版本、批量选择与真实配置作业关联、有限安全调试报告，以及已登记 proxy 地址和固定运维执行边界需要的约束。历史 SQL000–011 不修改，runtime 只对不可变事实有 SELECT/INSERT 权限。

新增 `apps/console-api/src/modules/toolbox/` 与 `apps/console-web/src/features/ToolboxPage.tsx`，固定请求 DTO、权限和游标沿用现有模块；不会新增通用 Admin 代理。新迁移、工作流种类、处理器和私有能力必须在实际模块、数据库和底层传输策略三处一致校验。

## 验证顺序

1. 源码验证匹配顺序、PCRE 预算、SSRF/redirect、参数质量、完整权限 tuple、草稿 owner/IDOR、CAS、失效私有许可、批量未知结果与秘密脱敏。
2. 隔离 PostgreSQL 完整 SQL000–012 迁移，验证复合 FK、不可变历史、软归档、审计原子性及 runtime 最小权限。
3. 单独部署 API/Web 与 SQL012，确认其余网关、存储、监控、门户和通知连续性及 Admin 网络隔离。
4. 新实际 1.5 对象验证节点和缓存、直接与审批失效、路由模拟对照真实代理、四种批量操作、五类回收恢复和本人草稿续编。
5. 浏览器检查只读按钮、危险二次确认、页游标、跨范围响应隔离和原键核验，产出安全截图与逐项请求证据。
6. 保留原失败，修复后附独立复验；最后核对所有成功写的审计/事务 outbox，并对产物和日志执行秘密扫描。

完成上述实际闭环后再进入 M10。当前计划不构成 M9 完成或商用就绪声明。
