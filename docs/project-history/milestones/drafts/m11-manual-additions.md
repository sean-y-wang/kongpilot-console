更新日期：2026-10-18。**草案，未合入正式使用手册或部署手册，不代表列举功能已经通过整体验收。** 发布前按 [验收清单](../../acceptance/m11-commercial-acceptance-checklist.md) 取得对应真实流程证据，核对最终界面、路由、支持范围与截图后，再合并到两本正式手册。

## 1. 用户使用手册拟增补：从配置预览创建工单

计划放在 [用户使用手册](../../../manuals/console-user-guide.md) 的配置导入与工单章节。以下为验收后的操作文案候选：

1. 在当前集群和工作区上传配置，生成预览并审阅新增、修改、删除、引用和恢复限制。
2. 点击页面开放的「创建工单」，输入页面要求的确认名称。平台重新读取当前配置；配置变化导致差异不再一致时，先返回差异页核对，不继续使用旧预览。
3. 提交成功后打开返回的**新计划与新工单**。以服务端显示的「工单有效期」为准，原导入预览与工单是两个独立记录。
4. 核对新计划的差异、范围、恢复基线与当前审批进度，等待独立审批。创建工单、审批通过和登记排程都不表示网关配置已经生效。
5. 需要定时执行时，按页面能力登记排程，核对当地时区、开始/结束时间和工单期限，再依据新修订重新审批并激活。
6. 到期后查看原日程、工单及逐步结果。只有实际业务结果与工单成功一致，才确认变更完成；结果待核验时保留原记录并停止相同目标的后续变更。

拟补提示：

- 新计划不能再次作为普通导入执行，也不重复创建同一张工单；按页面提供的原工单入口继续。
- 原预览过期不会给已登记的新材料续期；新工单也有自己的不可变期限。到期后基于当前配置生成新的独立变更，不续旧窗口或沿用旧票。
- 提交响应中断时使用原请求核验。不要清空浏览器记录、换键重发或在新标签页重新执行旧预览。
- 只有平台读取到严格匹配原账号、集群、工作区、原请求及来源计划的拒绝回执，才将对应本地事务归档。普通 409、404、登录失效或网络错误都不能单独证明没有产生工单或网关变更。
- 若拒绝原因为当前配置已变化，先查看原拒绝事实与最新配置；被处分的原预览保留历史，不再用于创建或直接执行。重新准备新预览须确认没有未核验的相同变更。

发布前待填：最终入口/按钮名称、正式支持类型、截图、新材料实际期限、长时独立审批与自然执行成功报告、SourceP 新 tab/刷新实测、未知处理入口。Target append、Promote、DELETE 等类型不得依据普通 Service 成功自动写为支持。

## 2. 用户使用手册拟增补：结果核验与恢复

候选文案：

| 页面状态/事实 | 用户应做的操作 |
| --- | --- |
| 提交成功，等待审批 | 打开原工单审阅状态，不重新提交 |
| 读取到严格匹配的拒绝回执 | 保存原拒绝记录，按当前配置核对新的差异；不重用已拒绝预览 |
| 尚在执行 | 查看原逐步回执，等待原执行；不并行提交相同目标 |
| 明确成功 | 核对业务可用性；需要撤销时准备新的回滚工单并重新审批 |
| 部分完成或结果待核验 | 保存集群/工作区、原键、工单、日程、执行 ID 和时间，联系值班人员；停止同一影响面的后续写入 |
| 原计划或执行窗口过期 | 不补执行、不续期；先核对是否已有部分变更，明确允许继续后再准备独立新计划 |

回收站恢复、快照回滚、门户凭证恢复与仅元数据核验各有独立条件。只有页面在当前权限和真实材料核验后开放的能力可以使用；没有通用“强制成功”或“清除未知”按钮。重新登录、换设备、数据库回退后查不到记录，都不是安全重试依据。

发布前待填：经故障注入验收的具体处置入口、适用事实与限制、值班联系流程；不把未实现的通用 unknown resolution 写成现有功能。

## 3. 部署与运维手册拟增补：SQL038/039 升级

计划放在 [部署与运维手册](../../../manuals/production-operations-guide.md) 的数据库迁移、M11 运维与发布交接章节。以下为待最终发布包验收的运维提纲：

1. 冻结真实发布 commit、API/Web/Portal 镜像、所有 SQL checksum 和锁文件。已应用的 SQL038 及历史迁移保持原字节，仅追加迁移；SQL039 不是改写旧版本账本。
2. 明确维护窗口，停止并排空全部旧配置 writer，包括后台 worker、旧 API 副本及相关自动化。旧 SQL038 writer 不认识已拒来源，不声明混合写版本安全。
3. 备份平台 PostgreSQL、Redis 持久状态与实际加密/签名密钥；记录当前审计链头、未完成作业、原键回执、各集群物理身份与对应网关配置快照。密钥不得放仓库、命令行历史、工单或截图。
4. 使用 migrator 身份执行发布包的真实迁移，核对实际版本账本与每条摘要。API 使用独立 runtime 身份并禁用启动迁移；失败保留原错误，不手工补成功记录。
5. 用实际 runtime 连接核对 NOSUPERUSER、无成员越权、无 schema CREATE 与 owner 权限；不可变事实表仅有声明的读/追加权限。检查新增函数固定 search_path 与实际 invoker/definer 设置符合冻结版本。
6. 在隔离验证范围完成真实原键拒绝、并发发布/拒绝互斥、回执越权、过期历史读取与来源计划处分测试；两个只持锁/回滚的连接不能代替真实两个 writer 的提交竞争。
7. 启动一致版本 API/Web/Portal/worker，验证 readiness、三端版本和真实能力投影；只有全部门禁通过后才开放本期对应写入口。保留停止前原日志和升级前备份。

发布前待填：最终 SQL 清单/实际摘要、迁移和并发报告、受支持升级路径、排空/恢复命令及真实现场演练结果。当前记录的 SQL000–039 共 40 条仅是 10 月 15 日历史基线，不预写未来发布包版本。

## 4. 部署与运维手册拟增补：期限、恢复与告警

运维需要分别观察预览期限、新工单材料期限、审批政策、计划修订、排程窗口、claim/lease、执行上下文和各原生步骤。后一个对象的较晚期限不会延长父授权；当前审批资格在发送前重新验证。不得通过加大全局超时、续原期限、切换 SID 或清除未知状态恢复旧任务。

环境恢复时先保持写入口和 worker 隔离，核对平台数据库、Redis、密钥与活动 Kong 的真实状态。恢复平台库不等于网关回退；恢复点之后发生的变更可能仍在 Kong 中。原键 GET404、空列表或 unchanged 回读都不能证明原请求未发送。

故障交接至少保存：原请求定位、版本与时间线、真实传输/回执事实、当前观测、影响范围和仍有效的保留。严格区分已知未发送、已知成功、部分完成与实际未知；没有足够证据时继续阻断，不能手改状态或重建原 packet/审批票。

告警与值班步骤待实际演练后写入：材料即将到期/窗口冲突、任务超时/未知、claim/worker 异常、审计/outbox 积压、通知失败、SQL/Redis/磁盘容量、实际读取预算与延迟。发布运行手册须列明支持容量、告警阈值、备份频率、恢复 RPO/RTO 与值班责任人。
