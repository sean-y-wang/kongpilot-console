# 审批人与执行人：当前行为与职责分离建议

**产品决定（2026-10-25 14:12 UTC+8）：保持现状，不增加“审批人不得执行”的硬规则。**

## 行为
- 工单（含门户凭证签发 / 轮换 / 吊销等 portal 工单及普通 workflow）全部审批阶段通过后，任何具备执行权限的账号都可执行，**包括批准该工单的审批人本人**。
- 硬规则只有：申请人不能审批自己的工单；审批与执行是两个独立的显式动作。

## 原因
- 执行能力 = 对该集群/工作区的 **write 权限**（门户等工单的 `capabilities.execute` 取决于集群 write；原生实体变更另需实体执行权限）。审批权限（`workflows:approve`）与执行权限相互独立，系统不按“是否为本单审批人”另行收紧。
- 实验室证据：`artifacts/M11/runs/20261025-1356-browser-e2e-matrix/`（cluster B 审批人可见执行按钮，本轮由 admin 执行）。

## 需要职责分离时的运维控制
1. 为审批人分配**仅含审批、不含集群 write** 的角色；执行账号单独授予 write。
2. 定期复核同时持有 `workflows:approve` 与集群 write 的账号。
3. 审计日志分别记录 `workflow.approve`（审批人）与 `workflow.execute`（执行人）的 actor，可据此事后核查同人审批并执行的情况（已在 lab 审计表实测核对）。
