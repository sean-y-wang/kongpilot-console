# M6 门户认证边界

门户开发者身份与控制台身份分别签发、分别保存会话。开发者只能提交自己租户内的申请；审核和 Kong 原生执行由当前有效的控制台会话完成。审批权限不包含执行权限，执行时再次校验工作流、门户和对应原生实体的当前权限。

## 最终发送前的检查

所有影响认证的 Kong 写请求，在 BFF 实际发送前进入独立的 `PortalAuthBoundaryService`。它使用数据库中保存的物理 Admin 地址范围查询发布和凭证历史，而非只依赖当前 `clusterId`。集群别名、地址重新登记、停用的发布及已吊销凭证不会使历史受管 UUID 变成普通对象。

Consumer、ACL、凭证的历史身份和 `kos-portal-api-<UUID>` ACL 组属于门户保留范围。普通实体接口、导入、恢复、标签迁移和嵌套关系请求不能引入这些授权事实。只有精确匹配当前密封计划步骤的私有执行能力可以变更受管对象。HTTP 请求中的 `approved`、`workflowId` 或相似字段不能创建此能力。取消或驳回的空申请只有在数据库证明没有执行、原生操作绑定和已签发凭证时才能释放预留；正常吊销或已证明释放后，重新申请分配全新的 grant、Consumer、ACL 和 Key UUID，原历史身份继续受保护。

发布证明保存实际 Service、ACL、key-auth 配置、目标版本的 schema、物理地址及终态工作流关系，使用 AEAD 和 HMAC 保护。私有证明不会进入公共文档或工作流差异。已发布但尚未签发凭证的 API 同样接受认证边界检查。

检查通过私有、短期、绑定当前会话和写操作的只读能力获取完整的 Services、Routes、Plugins 及已知受管 Consumer 的 ACL。该能力不开放任意路径、不查询全局凭证列表，不接受开发者 JWT，也不继承可伪造的“系统读取”请求标志。分页必须完成；超出预算、重复游标、缺失关联或检查期间元数据变化均拒绝写入。

## Kong 1.5 的实际插件规则

同名插件按照 Consumer+Route+Service、Consumer+Route、Consumer+Service、Route+Service、Consumer、Route、Service、全局的顺序选择；禁用实例不构成有效覆盖。检查区分 HTTP 和 stream 子系统。Kong 1.5 的 HTTP 插件筛选不会逐一匹配请求的 `http`、`https`、`grpc`、`grpcs` 协议，因此配置为 `https` 的插件仍可能影响 HTTP 路由。此行为已对照 1.5.1 的 Lua 源码并加入回归测试。

每个可达 HTTP API 必须保持有效的 key-auth 和不允许其他门户组进入的 ACL。匿名认证、相互覆盖的认证实例、未知自定义认证行为或无法证明安全的 Lua 插件使检查失败。其他与门户 Key 无关的独立认证 API 可以存在。

原生新增请求的分析模型使用目标真实 schema 中的默认值；插件 schema 仅查询旧路径 `/plugins/schema/{name}`。模型不会修改密封计划或实际发送请求。

发布预检与 Consumer 退役快照通过合法 `/plugins` 游标分页读取插件关系，并按真实 Service 或 Consumer UUID 匹配；不调用约定白名单之外的嵌套插件集合。扫描必须完整，后续页有未计划的 Consumer 插件或超过预算时停止退役。

## 一致性与容量边界

控制台原生写入使用物理地址级分布式锁，发送前重新检查权限、计划、审批和元数据指纹。Kong 1.5 Admin API 没有可用于整个对象图的事务或原子比较交换；网络外部直接写 Admin API 无法获得相同保证。专用管理网络必须只允许 BFF，运维变更也必须经过控制台。

当前完整认证检查设定 128 个路径、100 页、10,000 条记录、32 MiB、250 次调用及 120 秒的硬预算，纯图分析最多 100,000 个入口与 Consumer 组合。预算不足会明确拒绝变更，不截断图后继续执行。每个尚未终态吊销的受管 Consumer 需要两条读取路径；较大门户需在负载验证后调整可信服务器预算或实现等价的完整增量证明，不应把当前有界实现描述为无限容量。

数据库模式存在传播延迟。执行完成、回执终态和真实代理接受新配置分别核验；未知结果只能使用原租户、原操作人和原幂等键查询回执，不能自动重新发送写请求。

发布处于 pending 时，新操作默认被阻止。只有当前关联的密封计划、唯一执行、所有步骤和原生账本证明已知失败，且没有成功、进行中、未决原生变更、也没有尝试元数据步骤时，才允许用户明确确认一个新键、新计划。服务端在预检及事务内重复核验，并用 publication revision 与旧 workflow ID 作 CAS。旧键始终返回原回执，不自动重放；部分完成和未知结果需要先核验原操作。

## 证据

源码级测试覆盖当前 IAM 授权、私有执行能力、真实 AEAD/HMAC 发布证明、历史身份复用、保留 ACL 组、嵌套路径、协议子系统、图变化及预算失败。实际 Kong、门户登录、轮换、吊销、浏览器和清理结果统一写入 [M6 验收记录](../../project-history/verification/milestones/m6-verification.md)，未执行的门禁不计为通过。
