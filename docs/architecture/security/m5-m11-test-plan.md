# M5–M11 分阶段端到端验收计划

这是M4开发期间的测试设计，尚未实现或运行后续功能。所有真实验证遵守里程碑部署交接、独占串行写窗口、控制台审计和私有秘密引用规范。真实网络结果、受控故障模拟和外部供应商未验证项分别记录。

| 里程碑 | 真实端到端验证 | 安全和失败边界 |
| --- | --- | --- |
| M5 监控 | 启用真实1.5.1 Prometheus0.6插件，以隔离Route生成200/401/404/500和带宽/延迟样本，按相同时间窗对照Prometheus原始HTTP API与UI；集群、Service、Route及准确归属的工作区下钻 | 原生延迟桶单位毫秒；Consumer/workspace原生标签不存在，独立通道与缺失值必须明示；匿名/错scrape token、公网入口、其他集群及权限范围拒绝；序列标签歧义不得伪造归属 |
| M6 门户 | 独立开发者账号→申请应用/API Key→审批→带工作区标签的Consumer和key-auth→真实代理200；轮换后旧key拒绝、新key可用，吊销立即401；OpenAPI上传与Markdown展示 | 门户不能调用控制台用户/IAM接口或查看其他开发者凭证；存储/HTML脚本/外部引用攻击拒绝或转义；秘密仅授权首次/显式查看；驳回和未知创建回执不能重复发证 |
| M7 审计/事件 | 成功、失败和回滚写操作逐RequestId关联审计，重算链与diff；实体变更/证书/审批/漂移事件送受控Webhook和本地邮件测试接收器，验证订阅、重试、通知未读状态 | 运行数据库角色更新/删除审计拒绝；导出、diff、Webhook/邮件和死信记录无私钥/token；外部地址SSRF、伪造签名、跨工作区订阅拒绝；本地接收器结果不冒充Slack/飞书真实账户验收 |
| M8 快照/GitOps | 八类实体、Target和六类凭证建真实对象图，导出_format_version1.1 YAML，用选定真实decK1.x的validate/diff/sync对隔离环境核验；上传diff后逐对象apply，原ID恢复及原Key/Basic/JWT真实认证 | 先按真实decK版本确认每类实体的格式支持，不能凭YAML文本相似声明兼容；历史Basic缺原始密码时明确不可无损；导出权限/秘密独立；危险字段、未知写回执、依赖缺失与部分apply必须有逐项证据 |
| M9 工具箱 | 用真实Kong状态/缓存校验读及确认失效；对Methods/Hosts/Paths/Headers/regex_priority矩阵将模拟匹配结果与实际代理结果对照；批量标签/启停/迁移/回收逐对象核验 | 1.5无实际调试端点时不发不存在请求；基础和复杂匹配未覆盖规则必须显示模拟限制；批量操作二次确认，跨范围对象不因同批混入而执行；草稿不成为服务器授权来源 |
| M10 治理 | 受控只在隔离集群制造可创建的孤儿/引用/冲突/无owner情形，巡检和自定义lint输出定位证据；真实dev/prod漂移diff和Promote；修复后复检 | 1.5 DAO实际拒绝构造的非法引用用独立适配器夹具证明规则，明确非真实网关数据；Promote默认排除凭证和环境特定配置；目标与源权限都核验；新旧差异、引用变化、窗口冲突与未知执行无盲重试 |
| M11 工单 | 审批模式无工单/未审批写拒绝；多级/会签、计划时间和变更窗口、自动创建执行前真实快照、逐步执行日志、显式受控回滚及通知全链路，复用M6凭证流程 | 提交人不能审批自身禁自审工单，另一工作区/团队不得读审批；审批后配置变化须重新diff/验证；并发审批/执行仅一次，锁丢失与运行重启故障明确区分真实/模拟；未知执行先核验回执，回滚使用当前权限、新diff、审批和确认，完成后验证凭证实际可用 |

M5先依据已有只读真实证据[Prometheus能力研究](m5-prometheus-integration-plan.md)：只有连接/内存样本而无请求样本时显示不可用，不能把缺失曲线当成零流量。保留精确BFF来源的Admin ACL，不给Prometheus或采集器增加管理端访问权限。

每阶段保留初次发现与修复后的结果、测试命令、响应状态/RequestId和脱敏截图。每类秘密测试均记录真实认证成功/拒绝布尔结果，原始值只在私有临时引用中保留到全阶段扫描结束。最终整体回归需重新部署干净镜像并执行M0–M11完整关键链路；这些计划条目不是已通过的商用证明。
