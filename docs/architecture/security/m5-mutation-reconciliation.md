# 归档变更结果核验

M5 增加平台管理员显式核验入口，处理早期归档删除或恢复已经取得子步骤响应、但父变更回执尚未闭环的记录。该入口只发原生 GET，不重发删除、恢复或其他配置写入。

`POST /api/v1/clusters/{clusterId}/mutations/{operationId}/reconcile?workspaceId={workspaceId}` 要求当前平台管理员、当前集群变更写权限、Cookie CSRF 校验，以及 `confirmed: true` 和准确的归档对象名称 `confirm_name`。服务器自己定位完整加密归档，不接受客户端指定归档、结果或对象图。

核验在物理网关锁内完成：检查原操作、工作区、完整依赖图、每个子步骤的持久化响应，以及当前真实对象和共享引用。当前状态只能是与归档完全一致或已不存在，配置变化、读取失败、归属变化或证据不足均保持未知。对象图最多 200 个节点；超过预算不做部分判断。历史无工作区或变更外键的记录只有唯一、可核验归档才允许绑定，并追加审计。

全部步骤已落实时父回执变为成功；完全未落实或已知部分落实时变为失败，保留可恢复的归档和逐对象状态。部分落实不会被标记为成功，不会自动补发剩余步骤。提交前再次检查锁、权限版本、当前集群模式和归档，并用数据库原始微秒时间作 CAS；状态核验及归档更新与审计在同一事务提交。

**真正未取得响应的原生写包仍保持未知。** 超时或等待 15 秒不证明 Kong 的写入已经取消，即使一次 GET 显示不存在也不能安全释放未知操作。因此本入口只关闭具有持久化子步骤确认的父回执不确定状态。最终一致性、网关外部管理写入和故障处置仍需独立证据；不能通过换幂等键解除保护。

审批模式集群需要在后续统一工作流内处理核验，当前入口不会临时修改集群执行模式。监控 setup 另有原始幂等键和工作区绑定的专用父回执；普通原生操作回执不能替代这一多步骤回执。
