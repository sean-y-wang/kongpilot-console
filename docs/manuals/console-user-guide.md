# KongPilot 用户使用手册

**Kong 网关管理平台** · v1.0 · 更新日期 2026-10-15

KongPilot 将 Kong 的配置、团队权限、监控、门户与变更记录集中在一个浏览器入口中。运维与业务用户通过平台完成管理，无需直接访问 Admin API。英文产品名称为 **KongPilot**，中文产品名称为 **Kong 网关管理平台**。

本手册按实际操作任务介绍平台。部署、TLS、数据库、备份与值班见 [部署与运维手册](production-operations-guide.md)。页面展示依据当前权限和已启用能力；按钮缺失或禁用可能来自授权、版本、工作区状态或结果待核验，不表示应绕过平台操作。

本手册介绍平台的操作方式，具体入口以本站版本、权限和已开放能力为准。M11 整体、正式生产发布及商用准入尚未通过，未开放的自动变更保持关闭；本站开放条件见 [部署与运维手册的 M11 交接要求](production-operations-guide.md#19-m11审批政策与实体工单运维)。

## 1. 认识产品与账号

KongPilot 有两个入口：

| 入口 | 面向用户 | 用途 |
| --- | --- | --- |
| 管理控制台 | 运维、平台管理员、业务配置人员、审批人、审计人员 | 配置与管理网关、团队、门户、审计和恢复 |
| 开发者门户 | API 使用方与应用开发者 | 阅读文档、创建应用、申请和维护访问凭证 |

两个入口账号、会话和权限分离。开发者注册不自动获得控制台权限；控制台角色也不等于门户开发者身份。访问入口由组织管理员提供，生产使用 HTTPS。

平台固定对接 Kong OSS 1.5.x，按实际版本、插件清单和 schema 开启功能。工作区、RBAC、门户、审计、快照与工单由平台实现。平台仅经 Admin API 修改授权范围内的网关配置，**不改动 Kong 源码、镜像、插件实现或 Kong 数据库**；平台也不提供 Kong Enterprise 的原生工作区或运行时隔离。

## 2. 第一次登录：十分钟开始使用

1. 打开组织提供的 Console HTTPS 地址，确认浏览器证书正常。
2. 使用个人账号登录；若组织启用了 LDAP/OIDC，选择对应认证方式。不要共用管理员账号。
3. 首次要求修改密码时先完成修改；在「我的账号」检查个人资料与会话。
4. 在顶部选择正确的**集群/环境**，再选择**工作区**。后续列表、详情和变更始终绑定这个范围。
5. 打开「总览」，查看连接状态、版本、数据源与配置索引最近同步时间。
6. 根据授权进入实体列表；第一次写入前确认是否处于直接执行或审批模式。

登录失败先确认入口和认证方式。连续失败可能触发锁定；请联系管理员核对账号状态，不反复尝试弱密码。个人账号页面可修改密码、检查会话并撤销不再使用的会话；退出公共终端后关闭浏览器。

## 4. 列表、表单和安全确认

### 列表读取

列表使用后端分页及 Kong 的 size/offset 游标。上一页/下一页与已访问页缓存不等于可跳转任意页；搜索、标签与排序在后端支持范围内执行。搜索索引可能落后于网关实况，最终以实体详情的回读和观察时间为准。当前页条数不代表集群全量对象数。

### 表单填写

表单以探测到的 1.5 schema 渲染；必填、枚举、嵌套列表/记录由当前插件或实体约束决定。缺失、空值、false、0、空数组可能有不同含义。编辑秘密字段时按页面选择保留、替换或清除，不把脱敏占位符当真实值提交。

### 确认写入

先检查顶部范围、对象名称和执行模式，再提交。删除与批量变更需要二次确认；必须输入实际对象或计划确认名称。审批通过与执行完成分别判断，不能只看提交成功提示。

Kong 数据库模式存在数秒配置传播延迟。「配置生效中」不代表失败；关键变更完成后用真实业务代理验证。请求中断、超时或「结果待核验」时查看原回执，禁止换键重复提交。

## 5. 集群与数据源

### 登记集群

有权限的管理员在「集群管理」新增名称、Admin 地址、环境、标签及执行模式，然后进行探测。部署人员须先放行 BFF 到该管理端点的精确网络访问；不要把 Admin URL 配成公网裸端口或数据库地址。

探测先读取版本，再获取启用插件清单。1.5.x 不符时页面告警并限制写入。根响应不含 endpoints 时使用已验证的版本白名单，不擅自探测新版或企业 API。重复物理端点别名不能绕过集群锁或权限。

### 执行模式

- **直接执行**：有权用户确认后执行，记录真实结果与审计。
- **审批模式**：写入必须进入受支持的工单流程，全部所需阶段通过后，再由该类工单允许的执行者明确执行；原提交人和原会话要求见 [独立审批后执行](#235-独立审批后执行)。

审批模式下，核心实体、Consumer 凭证以及已接入的集群、数据源、工作区、身份权限、监控通道和实体说明均使用各自的变更预览入口。先审阅、确认提交，再独立审批和执行；准备或提交不代表配置已生效。页面入口及适用限制见第 23 节。未部署对应升级的站点继续使用已发布的受支持流程，不切换执行模式绕过审批。

### 数据源

在「数据源管理」添加 Prometheus/Loki 名称和地址，执行连通性测试，查看状态灯与最近探测时间。连通正常只证明数据源可访问；指标是否存在还取决于网关插件、采集、授权与时间范围。认证配置仅由有权人员维护，秘密不进入截图或日志。

## 6. 工作区与团队配置隔离

创建工作区时填写编码、名称、负责人和描述。平台用保留标签 `workspace:{code}` 自动归属实体，列表和详情按工作区与权限过滤。默认工作区收容符合默认归属规则的未打标历史配置。

工作区是管理视图软隔离：网关仍共享原生名称空间、Consumer、全局插件和运行时。直连 Admin、未迁移的历史对象或共享引用可能不受该视图约束。严密租户隔离需要独立网关/运行空间，由运维设计。

迁移流程：选择源/目标工作区 → 选择当前有权对象 → 生成预览，检查依赖和共享对象 → 二次确认 → 按集群模式执行或审批 → 查看逐对象结果。迁移主要修改保留标签，不自动更换名称或业务凭证。发现冲突或结果待核验时保留原记录，先核对实际对象。

审批迁移时：顶部保持**源工作区**，在迁移表单选择目标工作区；预览中检查父子对象、凭证和共享引用，然后输入**目标工作区名称**确认。审批模式点击「提交审批」，在「查看迁移工单」核对源/目标及完整差异；另一位具有两侧当前权限的审批人批准后，必须由**原提交人**显式执行，审批人不能代替提交人执行或自审。迁移成功后切换到目标工作区检查对象，原 ID 和凭证保持；工作区标签变化不等于运行时租户隔离。

当前审批迁移最多封存 **32 个实际 PATCH 对象、64 个共享或继承引用**，不能按根对象数估算限额。工单最长有效期为提交后 **14 分钟**，且不超过原迁移预览有效期；超过额度先缩小选择，过期或配置/权限变化后重新检查当前对象、生成新预览。已绑定审批的预览不能改 hash、延长有效期或切到直接模式执行。实体变更预览的审阅期限不会延长原迁移计划，也不会把旧工单自动转成定时任务。部分完成或待核验先读取原回执和全部步骤，不能重复提交整批。

总览中的配置数来自最近同步的索引；点击同步索引需要相应写权限。工作区流量还依赖监控采样，不能从实体数量推断流量或健康。

## 7. Services 与 Routes：发布业务 API

### 创建 Service

1. 打开 Services，确认集群/工作区。直接模式点击「创建 Services」；审批模式点击「提交创建工单」。
2. 填写唯一名称、协议、上游 host/port，必要时配置 path。
3. 按业务要求设置 retries、连接/读/写超时以及 TLS 校验相关字段。
4. 添加 owner/业务标签；支持的负责人/描述信息在注释入口维护。
5. 直接模式保存后进入详情核对实际 ID 和配置；审批表单确认后进入变更预览，按第 23 节提交、审批并执行。未升级的站点通过配置导入生成 Diff 后提交审批。

上游 host 指向 Upstream 时使用其准确名称；普通域名与负载均衡对象的使用方式需要区分。平台会拒绝 Admin、数据库及其他受保护控制面目标，不能通过上游配置绕过网络边界。

### 创建 Route

1. 在 Service 详情的 Routes 标签新增，或在 Routes 新增并绑定 Service。
2. 按业务配置 protocols、methods、hosts、paths 与需要的 headers/SNI/source/destination。
3. 检查 strip_path、preserve_host、regex_priority、HTTPS 重定向与 path_handling。
4. 保存后回读，验证真实 URL、方法、Host、请求头和上游实际收到的路径。

Route 使用 Kong 1.5 规则，不支持表达式路由。「运维工具箱 → 路由调试」可检查授权范围内的模拟结果；正则、范围缺口或多条相近路由仍需真实代理验证，详见第 21 节。

实体详情通过 Configuration、Routes、Plugins 等标签查看配置与关系。删除 Service 会影响关联 Routes/Plugins，须先查看对象图和恢复能力。

## 8. Consumers、凭证与 ACL

Consumer 是调用身份，主要字段为 username、custom_id、tags。创建后在凭证页按启用插件维护下列实体：

| 类型 | 用途 | 注意事项 |
| --- | --- | --- |
| key-auth | API Key | 仅授权读取，按业务策略轮换并验证旧 Key 失效 |
| basic-auth | 用户名/密码认证 | 历史 hash 不能推导原密码，恢复可能要求原文或轮换 |
| jwt | JWT 签名身份 | 维护 algorithm、key 与相应签名材料，测试真实 token |
| oauth2 | OAuth 客户端 | 可恢复原客户端配置；已吊销的access/refresh token不随恢复重新生效，须重新授权 |
| hmac-auth | HMAC 身份 | 保护 secret，按真实请求签名验证 |
| acls | 调用方分组 | 与 ACL 插件联合控制 Service/Route 访问范围 |

凭证列表默认脱敏。授权揭示仅用于当前操作，离开页面后按组织流程保管；不复制到普通工单、聊天或截图。凭证绑定 Consumer 不自动启用认证插件，仍需在正确的 Service/Route/全局范围配置插件。

普通 Consumer 与门户受管 Consumer/Key 的生命周期不同。受管门户凭证必须经门户申请、轮换/吊销流程维护，不能通过旧快照恢复已经退役的 Key。授权子实体页支持只持有少量子对象权限的账号访问其允许对象，不开放整个父对象范围。

审批模式下，Consumer 详情的创建、编辑和删除会打开凭证工单预览；也可进入「变更审批 → 发起变更 → 准备网关变更」，选择「Consumer 凭证」及真实所属 Consumer。凭证 ID 白名单可仅授权某个凭证，不扩大为整个 Consumer 权限。完整操作和恢复限制见第 23 节；门户受管凭证继续走门户专用流程。

## 9. 插件中心：配置认证与策略

市场按认证、安全、流控、转换、日志、Serverless 分类，显示实际启用插件与绑定范围。可用插件以当前 `/plugins/enabled` 为准，配置限制以当前集群的版本和插件 schema 为准；不承诺其他版本或企业插件。

操作步骤：选择插件 → 选择全局/Service/Route/Consumer 绑定 → 填写动态配置 → 确认 schema 校验 → 执行或审批 → 查看实例与代理效果。schema 来自 `/plugins/schema/{name}`。布尔值、数字、文本、枚举、数组、嵌套 record/map 和 array of record 使用对应表单。

同名插件匹配优先级从具体到通用：

1. Consumer + Route + Service
2. Consumer + Route
3. Consumer + Service
4. Route + Service
5. Consumer
6. Route
7. Service
8. 全局

上述是同名实例选择优先级，不是不同插件的执行顺序。查看页面优先级图与冲突提示，按真实流量验证。启停插件可能立即影响认证、限流或日志，属于写操作；批量操作需确认并查看每个实例结果。

日志/Serverless 类插件能够影响出站或运行行为，平台对控制面目标、敏感字段与能力做额外限制；不要用插件直连平台数据库或 Admin。

插件中心的专用创建/启停按钮在审批模式下仍可能禁用。核心 Plugin 配置可从「Plugins」实体表单或「变更审批 → 发起变更」准备工单；批量启停使用工具箱生成配置计划。按钮是否可用仍由实际绑定对象权限、插件约束和当前服务端能力决定。

## 10. Upstreams、Targets 与 TLS

### Upstream 负载均衡

创建 Upstream，配置 name、算法、slots 与 hash_on/hash_fallback 相关字段，再绑定 Service.host。实际 1.5 schema 决定允许的算法；界面联动显示适用哈希选项，不把其他 Kong 版本的功能混入。

在 Targets 添加 `host:port`、weight 和标签；权重 0 停用该逻辑地址的负载分配，与控制台回收删除是不同操作。Kong1.5使用追加记录表达权重变更，并可能自行清理已失效的历史记录；停用后历史和有效目标都为空也可能是正常结果。平台将原写入回执与当前目标观察分别记录，不将空列表单独当作成功或失败证明。健康检查包括 active/passive：按业务配置检查路径、超时、并发、健康/不健康阈值、状态码、间隔与 TLS 参数。主动检查要求上游确实提供对应检查入口。

健康页展示实际观察结果与时间。手动 healthy/unhealthy 是写操作，按权限和执行模式处理；置位不代替排查真实上游故障。

在 Upstream 详情的 Targets 页点击「添加 Target」，输入目标地址、0–1000 的整数权重及业务标签。点击「编辑」可调整权重和业务标签，目标地址保持只读；要使用另一个地址，应添加新 Target。工作区标签由系统管理。

直接模式确认后保存；审批模式先打开 Target 变更抽屉，点击「生成审批预览」，核对地址、原记录、权重和动作，再输入确认名称「提交审批」。通过「查看变更工单」完成独立审批和执行，提交本身不修改网关。设置权重 0 与删除都需要额外输入名称确认；删除使对象进入回收流程。

「健康 / 不健康」只在当前真实健康行能够对应同一 Target，且状态为 HEALTHY 或 UNHEALTHY 时开放。须先启用健康检查（主动或被动）；状态为 OFF、缺失或异常时先排查检查配置。手动置位仅作用于当前 Admin API 节点，不代表全部网关节点，不能自动回滚，也不支持定时执行。

如需按窗口创建或调整权重，使用「变更审批 → 发起变更 → 准备网关变更 → Upstream Target」中的「定时变更」；启用条件见第 23 节。

### 证书、CA 和 SNI

Certificates 支持粘贴/上传 PEM 证书与私钥，检查配对和到期提示；CA Certificates 管理信任材料；SNIs 将准确域名绑定证书。私钥不在普通列表明文显示，不提交到 Git。

替换证书后核对证书链、SAN、SNI 和代理 HTTPS。无引用证书与共享证书仍可能被其他配置使用，删除前检查依赖。Console 自身的 HTTPS 证书由部署人员维护，与 Kong 业务证书分开。

## 11. 权限、用户、团队与角色

管理员在「身份与权限」维护个人用户、团队成员、角色、克隆及权限矩阵。内置全局 super-admin/admin/read-only 与工作区级角色用于常见职责；自定义角色按最小权限设计。

四维权限为**模块 × 操作 × 范围类型 × 范围值**：

| 范围 | 用途 |
| --- | --- |
| global | 全局权限，谨慎授予 |
| workspace | 指定工作区内的操作 |
| tag_group | 对授权业务标签集合有交集的对象 |
| entity | 少量实体 ID 白名单例外 |

操作包括读取、写入、删除和审批；秘密读取是额外能力，不能因为可读对象就认为可读私钥或 Key。列表在后端过滤，单对象仍会验证 cluster/workspace/tags/ID。前端隐藏按钮之外，BFF 与 Kong 代理层继续检查权限。

权限继承：Route 权限可带来其 Service 的必要 read；Service write/delete 级联适用的 Routes 与绑定 Plugins；Plugin 权限结合绑定对象推导。授权具体实体前使用按名检索选取，并在矩阵中查看实际结果。

创建角色后用独立测试账号验证：read-only 无法写入；tag_group 只能操作匹配对象；entity 白名单只访问指定对象；跨集群/工作区拒绝。授权调整、团队变化、账号停用或工作区停用可能使已有页面和申请失效，重新读取当前能力。

## 12. Vitals：观察真实流量

打开 Vitals，选择集群/工作区、Service/Route 与时间范围（5 分钟至 7 天，实际可用历史取决于采集保留期）。查看 QPS、状态码、代理/上游延迟分位数、带宽、TopN 与节点。

| 指标 | 解读 |
| --- | --- |
| QPS | 时间窗口内的请求速率，不是累计请求数 |
| 状态码 | 查看 2xx/4xx/5xx 分布，结合认证、限流和上游错误排查 |
| P50/P95/P99 | 分位延迟，不是平均值；分别查看代理/上游维度 |
| 带宽 | 采集窗口内的流量速率，缺字节数据不补零 |
| Consumer/Service TopN | 在实际提供者与可用标签下统计，日志路径有估计边界 |
| 节点状态 | 最近采样/探测，不代表整个业务路径均健康 |

数据源未配置、无流量、采集延迟、权限或归属周期变化都可能导致空图。空样本不是零流量。工作区下钻由受管采集归属实现，不假设原生 Prometheus 带 workspace label。配置变化前的旧样本不会重新归属为新授权范围。

排查顺序：检查时间范围 → 数据源状态 → 采集和插件 → Service/Route 实际流量 → 让运维按同窗原始查询核对。不要靠开启全部插件解决空图。

## 13. 开发者门户：发布与申请访问

### 管理侧发布 API

1. 建立门户工作区与内容/开发者管理权限，配置名称、欢迎文字及外观。
2. 上传 OpenAPI/Swagger 文档，或在支持范围内从 Service/Route 元数据生成并核对。
3. 配置分类、描述和 Markdown 页面；预览目录和文档。
4. 检查 Service、Route 与访问策略，确认发布。
5. 审核开发者与应用，处理访问申请并查看结果。

门户要求隔离 API 访问边界。某个共享 key-auth 入口如果缺少受管 ACL，平台可能拒绝发布，防止新门户 Key 获得不应有的其他 Service 访问能力。应按页面 blocker 修正服务策略，不绕过拒绝。

### 开发者侧使用

选择已发布门户 → 注册并等待审核 → 登录 → 阅读 API 文档 → 创建应用 → 申请 API Key → 等待管理员批准和执行 → 在授权页面查看凭证 → 从真实业务代理调用。

批准不等于发证完成。管理员/执行者在基础审批流程中执行后，平台创建带工作区归属的 Consumer、凭证和访问策略，门户显示实际结果。申请失败保留原记录，按当前 blocker 修复并重新生成允许的独立申请，不重发未知请求。

### 轮换、禁用与吊销

按页面确认选择目标授权与操作。轮换后验证新 Key 可用、旧 Key 失效；停用/吊销后验证访问拒绝。历史备份或快照不授予重新启用已退役 Key 的权利。应用创建、编辑、归档与恢复记录事务内审计。

## 14. 审批与执行

在「变更审批」查看待处理申请、本人提交的申请及详情，核对申请人、集群/工作区、目标对象、Diff 和授权范围。

- 提交人确认范围后提交申请，记录原申请与请求标识。
- 审批人按实际权限批准或驳回，保留意见与历史。
- 该类工单允许的执行者在批准后显式执行，遵守原提交人及原会话要求，查看逐步结果。
- 撤销、失败或待核验保持真实状态；原记录不删除或伪改为成功。

门户凭证、配置发布、工具操作与配置治理复用统一工作流。历史工单继续按原政策执行；新政策支持顺序阶段及任一人、指定人数、全部候选人会签，不能用新政策补算旧票或修改旧计划。批准后权限、候选资格或配置变化仍可能阻止执行，需重新核对当前条件。详细操作和定时开放条件见第 23 节。

缓存失效和迁移由原提交人执行；批量配置按实际配置工单能力执行。审批通过只证明该冻结版本获得批准，不证明已发包或已生效；原 key、工单及步骤结果必须一并保留。详情按钮、有效期和恢复方式以该类型的真实工单为准，不把不同类型的期限或执行能力混用。

### 审批人能否执行（2026-10-25 决定）

审批通过后，任何具备该集群 write 权限的账号均可执行，包括批准该单的审批人；系统不设“审批人不得执行”的硬规则（执行权限 = 集群 write）。如需职责分离，请为审批人分配不含集群 write 的角色；审计日志分别记录审批人（`workflow.approve`）与执行人（`workflow.execute`）。详见 `docs/operations/approval-execution-separation.md`。

## 15. 删除、回收站与恢复

普通实体删除先读取依赖对象图，将恢复材料安全保存到回收站，再从活动网关配置移除。**删除会影响实际业务流量**，回收站不是“原对象仍继续工作”。

删除前检查 Service/Route/Plugin、Consumer 凭证、证书/SNI、Upstream/Target 的依赖和共享范围；输入确认名称，按集群模式执行。回收站预览根对象、原 ID、关系、时间、操作者与恢复限制。

恢复流程：选择回收记录 → 检查当前权限、目标范围、名称/ID 冲突和依赖 → 确认恢复 → 查看逐对象步骤 → 回读关系 → 验证业务 TLS 与认证。平台按可恢复图的依赖顺序处理，不保证缺失原秘密、已轮换凭证或外部上游仍可恢复。

批量删除先封存完整对象图，再按依赖删除。一个批次跨多个工作区时，恢复材料按**对象实际工作区分组**，每组覆盖该区所有选中根对象及受影响的 Routes、Plugins、Targets、SNIs 或凭证；恢复该组可能一次恢复多个根对象。作业步骤中的内部子对象归档应通过「完整回收图」入口检查和恢复，不逐个恢复不完整的 Consumer/凭证碎片。先阅读组内对象清单、实际已删除/未决状态及恢复限制；尚有未知原请求时交管理员按原回执核验，不把未删对象强行重建。

审批删除从列表「提交删除工单」或详情「申请删除」进入；恢复从回收站「提交恢复工单」进入。先确认实际名称，再查看完整预览，分别提交新的删除或恢复工单。恢复时顶部须切换到归档对象所属的当前有效集群/工作区，不能在另一区域直接恢复。提交只登记变更，审批与执行分别完成；通用操作和恢复限制见第 23 节。

永久删除与普通删除分开。它清除归档恢复材料，需要额外确认和当前能力允许；保留期到达不代表可以绕过确认自动清除。审计与不可变执行历史保留。

## 16. 审计、事件与通知

### 查一次变更

在审计日志按人、对象、操作、时间和集群筛选，打开详情查看 before/after 脱敏 JSON patch、来源、结果与关联审批。导出按权限进行，包含敏感信息的材料按组织流程保管。审计没有更新/删除入口。

若旧记录缺少历史字段或终态，平台保留原事实；不能将新执行拼接到旧请求记录中。查询不完整时保留请求标识并联系审计管理员核对。

提交报错时，保留页面错误中的请求标识。已认证写请求的失败会单独记录操作人、请求标识和 HTTP 结果，不保存表单内容。这类记录由具备全局审计权限的管理员查询；它只说明请求失败，网关是否已变更仍应查看对应工单及执行回执，避免重复提交。

### 配置事件渠道

通知渠道决定发到哪里，事件订阅决定哪些事件发到该渠道，本人订阅偏好只控制自己的站内通知，三者分别配置。

1. 运维先完成对应提供者与网络出口准备；提供者显示不可用时联系运维。部署分工见 [通知与审计运维](production-operations-guide.md#12-通知审计与健康检查)。
2. 有相应权限的用户进入「事件中心 → 通知渠道」，点击「新增渠道」，填写名称、当前可用类型、完整 HTTPS 目标或邮件收件人，以及该类型支持的认证。点击「提交配置」，输入渠道名称确认；审批模式还需完成对应工单。保存配置不会自动发送测试消息。
3. 进入「事件订阅」，点击「新增订阅」，填入当前工作区启用渠道的实际 ID，再选择事件类型、可选对象和业务标签，点击「提交订阅」并确认。事件类型之间为 OR，对象 ID 之间为 OR，标签之间为 AND，三类条件之间为 AND；过滤条件不会授予源对象权限。只建立渠道不会自动订阅事件。

渠道编辑不回填原目标或秘密。更换目标时勾选「明确更换目标与认证」，输入完整新目标并明确新认证；不提交脱敏掩码，也不自动沿用旧秘密。事件目录标明「需要观察通道」或「未实现」时，订阅本身不能补足观察能力。

需要验证外部渠道时，按能力点击「真实测试」并输入渠道名称确认，再到「投递与重试 → 详情与尝试」查看实际结果、时间与安全错误。测试排队不等于送达。真实测试/重放会向外部系统发送消息，遵循按钮确认与授权；只读查看不会发送。接收端需去重，未知发送结果先核验，不盲目重放；恢复渠道或订阅不会自动重放历史投递。

### 使用通知中心

顶部角标展示本人未读通知；进入通知中心查看内容、标记已读。维护接收规则时先选择「当前工作区」，打开「本人订阅偏好 → 新增本人偏好」，填写名称、事件类型及可选对象/标签，选择「启用站内消息」，点击「保存本人偏好」并确认。本人偏好不创建外部渠道，也不替代事件订阅；跨范围消息视图不提供此偏好入口。

本人通知不等于有权查看其他用户通知。权限撤销后迟到内容仍受当前授权验证；消息或邮件中的链接也不授予审批、执行或对象访问权限。查看通知后仍需回到原工单核对当前状态。

## 17. 配置快照、导入导出与回滚

### 第一步：选择配置范围

选择当前工作区、指定 Services 及依赖或完整集群。完整范围要求相应对象与秘密权限；共享引用标为只读，不自动取得修改权。页面提示不完整、需秘密、需轮换或不可恢复时先处理原因。

### 捕获快照

「配置快照」→ 手动创建 → 填写名称/说明/范围 → 输入名称确认 → 查看捕获作业 → 只有完成并发布的版本才可用于后续操作。详情检查对象/页/字节数、观察时间、一致性和凭证恢复限制。

定时捕获设置周期 5–10080 分钟、显示时区和保留 1–3650 天。恢复已归档策略后默认暂停，需审阅再启用。定时策略只捕获，不自动执行导入或回滚。

### 导出与下载

| 导出 | 适用任务 |
| --- | --- |
| 脱敏摘要（review） | 配置审阅；脱敏值不能部署 |
| 完整 decK YAML（deployment） | 格式 1.1，含可用私钥/凭证，要求秘密权限与受控保管 |

导出作业完成后再点击确认下载，按服务器给出的确认名称操作。下载许可绑定原用户、实际范围、导出 ID 和版本；会话或权限变化可能取消下载。不要把明文秘密配置提交到普通 Git。

快照归档/恢复元数据只管理平台记录，不修改网关；「生成回滚计划」才规划网关配置恢复。快照不包含整个控制台数据库，不能代替 RBAC、审计和门户的灾备。

### 导入、Diff 与发布

1. 在「导入导出 / Diff」选择目标范围和 merge/sync。
2. 上传合法格式 1.1 YAML；临时文本只保留在本次表单，清除不再使用的内容。
3. merge 处理明确新增/修改；sync 可能删除完整范围中缺失对象，必须检查删除预览。
4. 对 Basic 等历史秘密按可信原文选择保留/替换，不将 hash 或脱敏占位符冒充原秘密。
5. 上传生成预检和不可变 Diff，尚未执行网关写入。
6. 查看新增/修改/删除、字段 patch、共享引用、依赖、恢复能力与 blocker。
7. 确认后直接执行，或在审批模式且页面开放「创建配置工单」时签发**耐久配置工单**（`configuration_v2`）；批准后由原提交人执行。
8. 查看父作业与逐对象结果，回读并进行业务代理验证。

**Target 权重与耐久工单**：Kong 1.5 权重变更以追加新物理行表达。导入/回滚 Diff 中对已有 Target 的权重修改，在封存包完整（单条 POST、`allocatedNativeId`≠原 `nativeId`、路径与 HMAC 一致）时**可以**创建耐久配置工单；封存包不完整时服务端仍拒绝，并提示「Target 权重变更封存包不完整」。**不要**把该拒绝理解为“权重变更一律不可工单化”。

耐久路径最终行为（M11）：第二审批人批准 → **原提交人**执行 → 作业与工作流终态成功后，在 Upstream Targets 页或 Admin 只读回读应看到**新物理 ID**与目标权重（旧 ID 不再是有效行）。执行中断或回执未知时，按原幂等键只读核验，**不要**换键重放。业务排程对**完整封存**的 configuration_v2 Target 追加可登记定时；封存不完整仍拒绝，见第 23.9 节。

计划有版本、指纹和有效期，过期或配置变化需重新生成；不要执行先前未决计划。缺失、null、false、0 和空数组含义不同，格式投影省略不意味着清空字段。YAML 若要对已有对象做 merge 修改，须带上当前真实 ID，否则会被当作新建并可能触发唯一性冲突。

### 回滚

从目标快照生成「当前配置 → 快照配置」的新 Diff，检查新增、修改、删除与秘密恢复限制，再确认或审批执行。回滚不重放旧请求，也不能重新启用受管门户旧 Key。恢复后验证 Service/Route、TLS、Targets 和认证。

## 18. GitOps 与作业结果

GitOps 记录仓库显示名、40/64 位 commit SHA、流水线引用和真实作业 ID。它不自动连接 Git、push 代码或运行任意 shell。CI 的部署配置和秘密由组织受控流水线管理。

建议闭环：受控导出 → 安全保存/加密配置 → CI 上传 → 审阅不可变 Diff → 按模式批准/执行 → 原回执与逐对象核验 → 关联实际 commit。当前 decK 兼容工具固定 1.2.4，使用平台 BFF 专用授权，不直连 Admin；上传格式与发布操作见 [配置快照、导入导出与回滚](#17-配置快照导入导出与回滚)。

作业详情分别显示排队、执行、成功、失败、部分完成与待核验。某一步成功不等于父作业成功。查看实际原/有效对象 ID，尤其 Targets；实际回读通过才表明观察时配置匹配。

请求丢失或超时后，保留**原集群、原工作区、原请求 key、原作业 ID**。先使用原回执只读查询，不点击重复执行、不换键发送相同操作。

页面在满足服务端条件时提供「确认收口过期执行」：输入 `abandon:原作业ID`，停止对旧请求的重试引用，保留原成功、失败和未决事实。它不回滚、不重发，也不将原作业改成成功。若收口本身中断，继续读取原核验回执；没有完整证明时不能解除阻止。

需要完成剩余目标时，由有权人员核验当前配置后生成独立新 Diff，只规划尚需完成的变更。遇到未知结果先按 [原请求核验](#237-响应中断结果未知与原请求核验) 处理，必要时交值班人员核对原记录。

## 19. 三条常用业务流程

### 新建业务 API

确认范围和权限 → 创建 Service → 建立 Route → 配置认证/ACL/限流插件 → 审批并执行（如需）→ 真实代理测试 → 查看 Vitals 与审计 → 创建快照。

### 安全移除并恢复配置

检查依赖和调用影响 → 删除确认 → 查看回收图 → 验证入口行为 → 恢复前检查冲突与秘密 → 执行恢复 → 核对实际对象图和凭证 → 记录审计结果。

### 发布配置文件

捕获当前基线 → 上传 YAML → 审阅完整 Diff/删除/共享引用 → 确认或审批 → 查看每步回执 → 真实业务验证 → 关联 Git commit → 保存可恢复材料。

## 20. 常见问题与使用纪律

| 问题 | 处理建议 |
| --- | --- |
| 看不到菜单或写按钮 | 检查角色、集群/工作区、能力与当前状态；联系管理员，不直连 Admin |
| 搜索不到刚创建对象 | 刷新详情/索引，确认当前范围，避免将第一页当全量 |
| 审批已通过但配置没变化 | 检查是否显式执行、作业结果和传播时间 |
| 凭证显示为星号 | 需要额外秘密读取权限，不把星号复制为新凭证 |
| 回收站恢复失败 | 检查依赖、ID/名称冲突、原秘密与退役策略 |
| 指标图为空 | 检查采集、流量、时间范围与归属，不用零值猜测 |
| 门户拒绝发布 | 阅读认证/ACL 边界 blocker，修复真实策略 |
| 导出文件不能 sync | 检查 review/deployment、格式投影、工具版本及恢复限制 |
| 浏览器超时但网关已变化 | 读取原回执和实际配置；不要重试同一写请求 |

手机端可进行基础查看与常用操作；复杂 Diff、证书、权限矩阵和批量变更建议在桌面完成。保管个人账号，少授予全局权限，秘密不进入 URL/聊天/截图/Git。任何不确定写入先核验再操作。

第 21–22 节介绍工具箱和治理流程，第 23 节介绍变更工单与定时操作。站点开放范围由管理员维护；部署和交付要求见 [部署手册交付清单](production-operations-guide.md#16-正式站点交付清单)。

## 21. 运维工具箱：M9 操作

工具箱根据权限展示五个标签页；看不到入口先核对授权与站点版本，不直连 Admin 或更换账号绕过限制。read-only 账号可以使用获授权的读取和模拟功能，不能失效缓存、真实代理探测、批量变更、保存/删除/恢复草稿或迁移配置。

### 节点状态

选择集群后进入「节点状态」，点击「刷新」查看连接计数、数据库可达状态和观察时间。这些数据来自**当前登记 Admin 地址所连接的节点**，不代表整个网关集群所有节点，也不代表业务上游健康。节点统计需要完整集群级 toolbox.read；工作区读取权限不会自动获得节点总量。

### 缓存：只查精确键，失效不能回滚

1. 在「缓存」输入完整、确定的键，点击「查看」。允许字母、数字、点、冒号、下划线和短横线，长度不超过 256；路径、遍历和凭证缓存命名会被拒绝。
2. 查看是否存在、类型、字节大小与观察时间。页面只返回元数据，**不返回缓存内容**，也不提供枚举全部键或清空全部缓存。
3. 有完整集群级 toolbox.write 权限时，点击「失效缓存」或「提交缓存失效审批」，输入刚查看的**完整键**确认。
4. 直接模式查看真实回执；审批模式进入原工单，由独立审批人批准，再由原提交人执行。失败、过期或结果待核验保留原操作/工单标识。

失效仅作用于当前登记节点，Kong 后续按需重新生成缓存。Kong 1.5 没有写回缓存的恢复端点，因此**缓存失效没有回滚按钮，缓存材料也不是实体回收站对象**。不要将一次节点成功当作所有节点均失效。

### 路由调试：先模拟，再按需真实探测

填写方法、无查询参数的 URL、请求头及需要的来源/目的 IP、端口、SNI、Consumer ID，点击「模拟匹配」。页面展示候选 Route、Service 与同名插件选择后的执行顺序；模拟可以描述 POST 等方法，但这不授权真实发送这些方法。

结果是 Kong 1.5 规则模拟，不能证明真实网关唯一命中。当前范围之外的 Route/全局插件、未归属配置、缺 Consumer/SNI/IP 上下文、同优先级候选、脱敏匹配值或未知插件优先级都可能产生 **partial / 未验证范围**。这种情况下只查看已授权候选，不能把「未发现授权范围命中」理解为整个网关不存在路由。

正则使用隔离的 JS 兼容子集，**不是 Kong PCRE**。单次模拟最多 1,000 个 Route、64 个不同正则调用，计算预算 2 秒；正则 worker 上限 250 ms。原生清单采集另有分页/记录/字节预算，超额、超时或 PCRE 不支持会明确标记未验证，不保证所有候选已经排除。

真实探测需要集群登记的**代理地址**、完整集群级 toolbox.write 与命中 Route 当前权限。选中可探测结果后点击「真实代理探测」，输入 Route 名称或页面要求的确认值。当前只支持 **GET/HEAD**；GET 也可能触发业务副作用，确认前核对目标 API 用途。

输入 URL 的 Host、路径和 SNI 用于路由/TLS上下文，**不会把连接目的地改为用户输入的主机**；实际连接始终是当前集群登记的代理地址，受出站准入与受保护目标检查限制。平台不跟随重定向、不自动重试、不返回响应正文；仅展示状态、允许的响应头及有限观测信息。连接、TLS、首字节和总耗时来自 BFF 实际观测，不是 Kong 内部每阶段耗时；页面显示的模拟 Route 也不是实际响应 Route 的证明。

请求头仅用于本次诊断。Authorization/API Key 等敏感头需要时按组织凭证制度临时输入，不在 URL、草稿、截图或工单里保存；探测尝试后页面清空请求头。凭证不要粘贴进普通业务 header 名称以绕过限制。

### 批量操作：先生成配置计划

1. 选择「添加业务标签 / 启停插件 / 迁移工作区 / 移入回收站」与对象类型，填写最多 **50 个显式根对象 ID**；子对象与依赖还受完整图预算限制。
2. 添加标签只写普通业务标签，并保留当前工作区和其他标签；改工作区必须用迁移操作。插件启停只选 Plugin，不能用开关改变绑定。
3. 点击「生成变更预览」。标签、插件启停和删除进入配置计划；工作区迁移进入第 6 节的专用预览。
4. 在 Diff 页核对当前 CID/WID、实际受影响对象数、依赖/共享引用、缺失恢复材料与 blockers，按页面输入计划名称；删除还需确认真实删除数量。
5. 直接模式执行，审批模式提交固定配置工单；批准后显式执行。查看原作业与**每个对象**的结果，再用业务代理核验。未知一步会阻止后续继续，不重复运行整批。

批量删除进入按工作区分组的完整回收图，按第 15 节恢复；单个内部成功回执不能替代整组完整性。只读账号不能通过批量入口写入，前端隐藏之外后端和 native 代理层也拒绝越权。

### 我的草稿：个人编辑材料，不是秘密保险箱

在实体表单使用「保存草稿」后，进入「我的草稿」查看名称、类型、版本和更新时间；点击「继续编辑」重新读取当前实体并恢复非敏感输入。列表使用上一页/下一页游标；「已删除」筛选中的草稿可输入名称确认恢复。删除是软归档，保存/归档/恢复受版本 CAS 和原键回执保护。

草稿仅属于原用户与原集群/工作区，其他用户即使有管理员身份也不能直接读取个人材料；保存不会修改 Kong，在审批模式也不等于工单已批准。继续编辑、保存和真正提交仍重新检查当前对象权限、schema 与范围，草稿不能续签旧写许可。

草稿最多 64 KiB、嵌套深度 12、单数组 500 项，保留 false/0 等非敏感编辑值；**不保存私钥、证书原文、API Key、密码、令牌、认证头、Cookie、带凭证地址或 Serverless 函数/脚本**。命中禁止材料会拒绝保存；去掉敏感值后再保存，提交时按当前秘密保留/替换流程填写。不要把草稿当脚本仓库、凭证恢复材料或可恢复快照。

### 超时或断线：核验原回执

保留原账号、集群、工作区、请求 key、操作/作业/迁移计划/工单 ID。使用当前界面的原回执入口读取结果；平台接口分别提供 cache `toolbox/operations/by-key/:key`、draft `drafts/operations/by-key/:key`、配置 `configuration/jobs/by-key/:key` 与基础工单原回执。接口仅用于同一提交账号的授权核验，不是开放代理。

**unknown / uncertain 不等于失败。** 不点击重复执行、不更换 key 发送相同写请求、不因一次 GET404 猜测原请求未发送。已知成功步骤保持成功，未知步骤交管理员按原持久记录处理；若需要完成剩余目标，核验当前配置后生成明确的新 Diff。自然过期不会撤销网关已执行步骤，也不会自动恢复删除内容。

工作区迁移的原生步骤已经全部确认、仅工单账本尚未完成时，原执行人可在工单详情使用「工作区迁移结果对账」入口。保持原源工作区，填写 **原 execute 请求**的幂等键，先核验回执；只有服务端确认完整成功材料、当前两侧权限和审批资格后才开放「只对账迁移元数据」按钮。确认沿用原键，仅提交原工单的终态记录；后端可以读取当前对象核对，**不会重发迁移 PATCH**。原失败响应与审计仍保留。计划过期只允许这类已完成变更的账本核验，不能继续发送过期计划的网关写入。

## 22. 配置治理

进入「配置治理」后按授权显示「巡检报告 / Lint 规则 / 配置漂移 / 环境发布 / 调度」五个页签。页面始终使用顶部当前集群和工作区；切换范围后不要沿用上一范围的选中对象或未知请求键。

### 巡检报告与修复

1. 在「巡检报告」选择当前工作区、指定 Services 或完整集群，点击执行巡检。完整集群需要相应全局权限；服务根对象最多 100 个。
2. 阅读报告质量、观察时间、覆盖范围、规则结果和问题列表。`complete` 表示此次有界读取与检查完整，仍是控制台围栏下的观察；外部直连 Admin 的并发变更不会因此自动受控。`partial / incomplete / not_evaluated` 不能当作“没有问题”。
3. 按严重程度、规则筛选问题。关系、引用、重复/潜在路由重叠与 owner/说明问题使用当前真实对象和 schema 检查；权限投影不产生全局不存在的结论。路由潜在重叠不等于已经证明同一请求必定冲突。
4. 选中确认的问题后点击修复，填写页面列出的固定字段。支持 owner 标签、仅加密协议、Service 超时、名称、引用替换/清除、未使用证书归档、基线插件配置与平台说明。后台重新检查当前问题与对象权限；变化后需生成新报告。
5. 原生修复生成配置合并计划，审阅 Diff、影响对象与 blockers 后，按当前集群直接执行或提交审批。未使用证书归档使用完整回收图，不物理删除。平台「说明」属于控制台元数据：直接模式完成保存，审批模式生成固定元数据工单；它不会写入 Kong 不存在的 `description` 字段。

完整集群巡检采用显式全局流控基线 `rate-limiting`，发现缺失时只报告，**不自动开启全局认证或流控**。补齐前审核插件 schema、限额、共享存储与业务影响。工作区或服务报告不能证明全局基线是否存在。Portal/Vitals 管理的边界配置不通过普通修复绕过其专用流程。

### Lint 规则

新建规则填写稳定编码、名称、严重程度、对象类型与固定谓词；编码最长 96、名称 128、说明 500 个字符，说明留空使用名称。规则使用受限 JSON DSL，支持字段存在、类型、枚举、数值范围、标签、HTTPS、引用及有界正则，不执行 SQL、JavaScript、网络请求或任意 JSONPath，也不能读取秘密字段。

例如，为 Service 检查负责人标签：

```json
{
  "code": "team.owner_required",
  "name": "Service 负责人标签",
  "severity": "warn",
  "given": { "entityTypes": ["services"] },
  "then": { "path": "tags", "op": "tags_contains", "value": "owner:", "match": "prefix" },
  "enabled": true
}
```

编辑使用当前 revision，新版本不会覆盖旧内容；克隆生成新编码。归档/恢复输入真实名称确认，按集群模式直接保存或审批。内置 HTTPS、超时与命名规则可通过同编码配置覆盖或停用；固定关系/owner/说明等结构巡检不会被自定义 DSL 替换。正则超时或预算耗尽显示未评估，不能据此判断规则通过。

### 双环境漂移

在「配置漂移」指定另一登记集群和工作区，可分别限定源、目标 Services。两侧都需要当前读取权限，两个登记项指向同一物理 Admin 地址时会拒绝比较。

比较按逻辑名称与关系对齐，原生 UUID 不要求相同。默认排除凭证、私钥/敏感插件字段、证书原文以及环境相关地址/匹配字段；因此“无差异”只针对此次显示的政策和覆盖范围，不能等同于字节级全配置一致。切换“比较环境字段”前核对授权和政策，查看新增/修改/目标独有对象以及字段差异；重复或匿名身份不明确会阻止发布。

### 环境发布

从完整比较进入「环境发布」，选择源对象、指定已有目标映射，按需要填写目标专用配置。资源选择器提供全部已授权资源与差异筛选；没有普通字段差异的 Consumer 也可显式选择用于凭证发布。服务端分页，不把当前页当作全部资源；共享只读引用和 Portal/Vitals 管理项不可作为普通可写选择。

默认不发布环境字段、秘密或凭证；已有目标中的排除字段通过配置合并保留，新 Service 的目标 host、新 Upstream 的目标地址或新 Route 匹配信息不足时会阻止生成可执行计划。发布凭证需要同时勾选「显式发布凭证」和「显式发布秘密配置」，确认真实凭证内容会写入目标环境；随后可选择六种受支持类型，建议按实际预算分小批。勾选类型不绕过源凭证集合完整性、恢复材料或当前授权检查。

输入页面要求的 `PROMOTE <比较ID>` 后生成**真实目标集群/工作区**配置计划。目标为审批模式时继续提交目标工单，批准后由原提交人执行。检查目标范围、Diff 与逐步结果，不在源工作区执行目标计划。发布会在实际执行入口与每次原生发送前重新验证来源权限、配置（包含未公开的原生字段）、选择和连接；来源变化或授权撤销会阻止发送，不能通过普通配置执行或复制计划绕过。升级前的历史比较缺少这类私有来源验证记录时，仅可查看历史，需要重新比较后发布。

勾选秘密/凭证不代表已经取得可用恢复材料。只有服务端真实授权捕获的完整材料才能用于该类发布；返回 blocker 时保留排除策略或使用现有受控凭证流程，不复制星号、脱敏值或 Basic 密码哈希当作原密码。

需要撤销发布时，在目标集群进入配置快照，选择该次执行实际关联的执行前快照，按当前状态生成新的回滚预览。仔细确认将删除的对象、凭证与完整回收内容，再按当前模式确认执行或审批。不要延长过期计划、改写旧快照或重发未知请求。完成后分别验证保留凭证可用、应撤销凭证失效及源环境未受影响。

### 定时检查与通知

在「调度」设置巡检/漂移、当前范围、5 分钟至 7 天的间隔、时区与告警阈值。调度只读取和检查，**不自动修复或发布**。间隔是持续时间，不是 cron 或业务变更窗口。调度元数据修改、暂停、归档/恢复同样遵循直接/审批模式。

服务端每次验证真实策略版本、原负责人当前资格、范围、连接及实际已登记 occurrence。漂移达到阈值后通过 `config.drift` 订阅通知；通知只指向报告，不暴露另一侧名称、配置或秘密。报告质量不完整时不推进可信漂移基线。

运行状态显示原 occurrence ID。权限失效显示 `paused_authority`，修正授权后明确保存新政策版本；过期 lease 或未知持久结果显示 `uncertain` 并阻止后续运行。不要点击重复执行或修改旧历史。保留原记录，核验实际报告；需要另行检查时归档被阻止的调度，明确创建新调度，而非重放原 occurrence。

### 原请求结果核验

治理原回执入口为 `clusters/:clusterId/governance/operations/by-key/:key`，绑定原账号、集群/工作区、种类和键。纯 GET 不重新捕获、不重新编译、不生成新修复、不发送网关变更。

修复响应丢失时，父请求可能仍待核验而真实子计划/说明工单已登记；可打开已知原子链接，但不把链接存在当作整个修复已完成。页面允许时输入 `reconcile:<原键>`，只补全父请求与**已确认、同源实际子回执**的元数据关联。它不重复保存说明、不重建工单、不执行计划或发送 native 请求。未知步骤继续保留原键；不要换键重发相同变更。

## 23. M11：变更工单、独立审批与恢复基线

本节适用于已部署对应 M11 功能的站点。管理员须先确认本站开放范围；尚未开放的入口保持禁用，不从旧接口绕过。

### 23.1 找到需要处理的工单

打开「变更审批 → 变更工单」。通过「我的工单」选择「当前授权范围 / 我提交的 / 待我审批」，再按状态筛选。列表显示执行模式、当前审批阶段、票数与提交时间；使用上一页/下一页读取后续工单。

在「工单展示方式」切换「列表 / 看板」。看板分为「待审批 / 待执行 / 执行中 / 执行结果」，点击卡片进入原工单。两种视图使用相同筛选和服务端分页，各列数量只代表当前页。尚待审批或执行的工单超期会显示「已逾期」；角标不取消、执行或续期工单，也不证明变更窗口没有冲突。

进入详情后核对集群、工作区、工单类型、计划版本、指纹和有效期。查看「审批进度」「变更进度」以及该类型实际提供的差异、恢复基线和逐步结果。按钮由后端当前能力决定；“待我审批”仅表示当前阶段具备投票资格，不授予整个工作区的配置权限。

### 23.2 管理审批政策

具有权限的管理员进入「变更审批 → 审批政策」，找到对应类型并点击「编辑政策」。

1. 设置「工单有效期（小时）」为 1–168 小时，并确定是否要求「不同阶段使用不同审批人」。提交人不可审批自己的工单。
2. 按先后顺序设置阶段；支持「任一人通过」「达到指定人数」「全部候选人会签」。设置人数时确保候选人数足够。
3. 从「指定用户 / 团队成员 / 角色成员」按名称搜索选择。目录可以切换当前工作区、当前集群和全局目录；能搜索到记录不等于具有该张工单的审批资格。
4. 点击「发布新版本」，按要求输入政策名称确认。直接模式保存新版本；审批模式先生成政策变更工单，执行后才生效。
5. 归档或恢复政策同样需要确认。新版本不覆盖历史政策、已冻结的候选名单或原审批意见。

候选人在提交时冻结，后来加入团队或角色不会自动获得旧工单投票权。候选人停用、凭证状态变化、被移出原团队/角色或失去审批范围时，旧批准可能无法支持执行。会签门槛不会因移除候选人自动降低；不要修改旧票或借他人账号完成审批。

### 23.3 从业务页面发起变更

按当前集群执行模式，原业务页面会直接执行确认后的变更，或打开对应审批预览。审批预览中的实际对象、影响范围、确认名称和有效期由服务端生成。

| 业务入口 | 审批模式中的操作 |
| --- | --- |
| 核心实体列表、详情和回收站 | 「提交创建工单 / 提交变更工单 / 提交删除工单 / 提交恢复工单」，进入「发起变更」审阅对象图 |
| Consumer 详情中的凭证列表 | 「创建凭证」、编辑或删除，打开「凭证变更工单 / 凭证删除工单」 |
| Upstream 详情中的 Targets | 「添加 Target / 编辑 / 健康 / 不健康 / 删除」，生成预览后提交独立工单 |
| 集群管理、数据源管理、工作区管理 | 正常填写原表单并确认，进入「审阅配置变更」 |
| 身份与权限 | 用户、团队、角色、权限、成员和角色绑定等受支持修改，进入「审阅身份与权限变更」 |
| Vitals 监控 | 「配置监控通道」，选择数据源及采集方式后进入「审阅监控通道变更」 |
| 实体详情的「实体说明」 | 编辑、删除或恢复说明，进入「实体说明变更审批」 |

准备阶段只形成受保护的预览，不修改活动网关对象。核对「现有配置」「拟提交配置」和「影响范围」，输入页面显示的真实确认名称后点击「提交审批」或「提交工单」，再点击「查看工单」。关闭预览不取消已提交工单；放弃尚未提交的预览不会清除未知请求。

集群、数据源、工作区、身份权限及实体说明是平台侧元数据。其工单不会因此取得网关写入权。监控通道配置包含实际全局插件变更，应按网关变更审阅。每类操作仍需原业务权限和对应工单权限，拥有 workflows 权限不会扩大实体授权。

### 23.4 网关实体、Consumer 凭证与 Target

在「变更审批 → 发起变更」点击「准备网关变更」，可选择「网关资源 / Consumer 凭证 / Upstream Target」。网关资源支持八类核心类型；凭证必须选择真实所属 Consumer 和凭证类型；Target 必须选择所属 Upstream，编辑权重时选择当前真实 Target。

填写 schema 表单后生成预览，检查新增、修改、删除、父子绑定、差异、影响对象、网关步骤和恢复限制。按页面要求输入确认名称，审阅后再提交工单。删除和恢复需要各自的二次确认，Consumer 删除还会使关联认证失效。

Consumer 凭证列表支持 key-auth、basic-auth、jwt、oauth2、hmac-auth 和 ACL。审批时检查 Consumer、类型、原凭证 ID 与动作，预览和审计对秘密脱敏。Basic-auth 可恢复删除要求平台已经保存原密码；不能用网关保存的哈希代替。OAuth2 客户端恢复会保留原客户端标识与可恢复秘密，但已吊销的旧令牌、刷新令牌和授权码不会复活，应用需要重新授权。

Kong 1.5 调整 Target 权重会为同一地址追加新记录和新 ID，不能把旧 ID 当作更新后 ID，历史数量也不等于有效目标数量。Upstream 的 Targets 页可即时调整 0–1000 的整数权重和业务标签，地址在编辑时锁定；权重 0 停止该地址承担新的负载，需要额外确认。网关可能清理失效历史，平台会分别展示原写入回执和当前有效状态，不要求历史永久保留。

Target 手动健康置位须启用健康检查（主动或被动），并有与同一 Target 匹配的 HEALTHY 或 UNHEALTHY 观测；OFF、缺失或异常状态不会开放操作。此操作仅作用于当前 Admin API 节点。健康观测无法还原之前的手动置位状态，因此此类工单不支持自动回滚，也不提供定时健康置位；如需再次调整，依据当前状态发起新变更。

API Key、密码、私钥、JWT/HMAC 材料只填写专门的授权表单，不放入审批意见、普通说明、URL 或个人草稿。保存后需要显示秘密时，只使用页面明确提供的本次授权显示入口。

### 23.5 独立审批后执行

1. 独立审批人打开「待我审批」，核对对象、差异、影响范围、恢复限制、有效期和当前阶段。
2. 填写意见，点击「批准第 N 阶段」并输入确认名称；驳回必须填写原因。上一阶段未通过时，下一阶段不能先行批准。
3. 后续候选人分别使用个人账号完成投票。同一阶段每人一票；政策要求阶段间不同审批人时，同一人不能重复批准另一阶段。
4. 所有阶段通过后，由当前工单详情允许的账号执行，不能仅凭已批准或管理员身份代执行。网关实体、缓存失效和迁移等要求原提交人执行；控制面、身份、监控及实体说明等工单还可能绑定原提交会话。页面提示原账号或会话不匹配时，先按原请求只读核验，不借用他人会话。
5. 对网关实体工单，可先点击「检查当前恢复条件」。这只读取当前条件，不发送网关变更，也不代表恢复基线已经保存。
6. 点击「执行已确认计划」并再次确认。平台重新检查当前授权、审批人资格、范围、配置和来源；网关写入前保存真实所需基线，条件不满足则阻止发送。
7. 查看最终状态及逐步回执，回读实际配置；网关变更还需验证真实业务代理、TLS、认证和流量。

**驳回与撤销**：审批人要拒绝当前变更时，在原工单详情填写「审批原因」，点击「驳回变更」，输入工单名称确认；要放弃工单时，由当前具有该能力的账号点击「撤销工单」并确认工单名称。只使用详情实际开放的按钮，再查看原回执和最新状态；响应中断时按 [原请求核验](#237-响应中断结果未知与原请求核验) 处理。

驳回、撤销工单和撤销排程是不同操作，均不能当作已生效配置的回滚。已登记任务还须核对 [定时变更](#238-定时变更) 或 [业务排程](#239-业务排程) 的原记录，不根据关闭预览或工单提示推断任务已取消。需要撤销已生效配置时，使用下节的新回滚工单。

集群执行模式变更、工作区归档或身份权限修改可能让当前列表消失或使后续写入失去授权。完成后的原回执只证明该次事实，不恢复旧权限；从原操作记录核验，不切换到默认工作区或其他账号继续执行。

### 23.6 依据原基线生成新回滚工单

从已闭合且当前允许回滚的网关实体工单点击「准备回滚工单」。平台依据真实执行前基线和当前配置生成新的变更预览；检查后重新提交、独立审批并执行。回滚不重放原执行请求、不复用旧票，也不覆盖旧成功、失败或部分完成历史。

Target 权重回滚仍遵循追加新记录的语义；手动健康置位不能自动回滚。秘密缺失、外部引用变化或原生结果仍未知时，以恢复限制为准。平台侧配置或身份元数据不能套用网关快照回滚；需要撤销时，依据当前对象和权限发起该业务支持的新变更。

恢复回收对象后检查原 ID、完整关系和凭证可用性。恢复 OAuth2 客户端不恢复旧令牌；恢复共享对象也不会授予额外范围权限。永久删除恢复材料是另一项危险操作，不能顺带执行。

按任务选择恢复入口：[普通 Consumer 凭证](#8-consumers凭证与-acl)、[门户凭证轮换与吊销](#13-开发者门户发布与申请访问)、[回收站完整对象图恢复](#15-删除回收站与恢复)、[快照生成新回滚计划](#17-配置快照导入导出与回滚)。这些入口的凭证限制和审批要求分别适用。

### 23.7 响应中断、结果未知与原请求核验

遇到超时、中断或「结果待核验」，保留原页面记录、请求键、集群/工作区、工单及执行 ID，停止同一目标的后续变更。

| 当前状态 | 先核对什么、如何继续 |
| --- | --- |
| 执行中 | 读取原工单和逐步回执，等待当前执行的真实结果；不并行提交相同变更 |
| 失败 | 查看原失败原因、已尝试和已成功步骤；失败状态本身不能证明未发送或没有业务影响 |
| 部分完成 | 核对每一步及当前对象，保留成功部分；原结果明确后，仅为仍需完成的目标生成新预览并重新审批 |
| 结果未知 / uncertain | 保持原记录和阻断，先只读核验，必要时联系值班人员；不能当成明确失败重试 |

- **准备响应未知**：在对应页面使用「核验原请求」「核验原回执」或已有预览入口。已接入的实体、控制面、身份、监控和实体说明准备器各有自己的原键只读核验；不存在可以查询任意类型的通用恢复按钮。
- **提交、投票或执行响应未知**：在原详情点击「只读核验原请求」，先核对原回执，再读取最新状态。它不重复提交或发送网关变更。
- **部分完成、执行中或结果未知**：按逐步事实处理，已成功步骤可能已经影响业务。缺审计、一次查询 404、空列表或期限已过，都不能证明原请求没有发送。
- **原准备记录暂未观察到**：保留原请求键继续只读核验；页面显示未观察到，不等于允许换键重新提交。
- **权限、政策或配置已改变**：保留原记录，交运维查明原结果；允许继续时，再按当前状态准备新的剩余变更并重新审批。

Target 原结果核验、部分恢复元数据收口以及门户凭证元数据恢复，只在服务端能够证明精确原事实时开放。它们不重发网关变更，也不是通用“修复失败”。保留原失败响应和审计，不手工改状态。

刷新登录不会延长计划或消除未知请求；对绑定原提交会话的工单，新登录也不会自动取得原会话的执行权。清空浏览器存储、换设备、换账号或从旧备份查不到记录，都不是安全重试依据；保留阻断并联系值班人员。

### 23.8 定时变更

定时写入需管理员单独启用，完成本站专项验收后才可使用。页面可见不代表后台已经开启。

在「发起变更」准备受支持的网关资源、Consumer 凭证或 Target 创建/权重变更时，勾选「定时变更」，填写「计划执行时间」「窗口开始时间」「窗口结束时间」。此入口按 **Asia/Shanghai** 展示；窗口开始包含、窗口结束不包含，且不得超过原计划或工单有效期。确认 `scheduled-change` 后生成定时预览，再按该版本提交并完成全部审批。

进入「变更审批 → 定时变更」，打开原记录，按当前能力确认「激活定时变更」。激活只是登记待调度任务，不表示配置已生效；继续查看工单、日程终态与逐步回执。平台到期后使用受限后台委托重新验证权限、审批资格和窗口，不借用他人 Cookie。退出登录不等于取消已激活任务。

未领取的任务可按页面能力「撤销定时变更」。已领取、部分执行或结果未知时可能拒绝取消；取消不能撤销已成功配置。错过窗口不自动补执行，审批人资格变化或来源失效可能阻断任务；不能延长旧期限、重置状态或换键重启原任务。

未由管理员开放的定时类型保持关闭。快照捕获、巡检和漂移的只读调度不会因此取得自动发布、修复或回滚能力。

### 23.9 业务排程

配置发布、环境 Promote 和门户凭证申请使用「业务排程」，与普通实体定时记录分别管理。管理员须确认本次发布已开放对应适配器。

在支持排程且尚未投票的工单详情填写「执行时间（本地）」「窗口开始（含）」「窗口结束（不含）」，先核对浏览器本地时区；该表单与上节固定上海时间的表单不同。点击「登记排程」，输入 `schedule-workflow` 确认。登记会形成新计划修订，必须按新版本重新审阅并完成审批；已有投票、执行或过期计划不能直接转换为后台任务。

在「变更审批 → 业务排程」查看当前集群/工作区的记录，或回到原工单按能力激活、撤销。登记和激活回执都不代表业务执行完成；须继续核对实际执行和业务结果。遇到未知响应使用「核验原回执」，不换键重发。

业务排程不延长原配置发布或迁移计划。窗口须在源计划和工单期限内；过期后重新读取当前配置、生成新预览并审批。尚未开放的业务类型不用于自动变更。**含 Target 权重追加步骤的 configuration_v2 工单**：封存包完整（单条 POST、`allocatedNativeId`≠原 `nativeId`、路径与 HMAC 一致）时可在作者修订、激活与预领取阶段登记定时；封存不完整仍返回 `WORKFLOW_SCHEDULE_CONFIGURATION_TARGET_APPEND_UNSUPPORTED`。自然执行依赖站点 `BUSINESS_SCHEDULES_ENABLED` 与完整审批窗口。lab 已验证 admit→approve→activate→自然 claim→自然 execute，Kong Target 权重回读 55（定时 configuration 调用预算 1000；其它执行仍 500）。高 CPU 争用下仍可能窗口到期 fail-closed（权重保持 100）；正式商用前须完成生产 compose 与浏览器全链路。未开启排程时请用即时审批执行。

**定时 configuration_v2 未知结果（运维）**：已发送但结果不明的 mutation 走 `reconcile-configuration-unknown-result` / 双人 `request|confirm-configuration-unknown-result-abandon`（只读 Kong、零写）。**从未打开 mutation 行、远端发送未启动**的 uncertain 作业走 `reconcile-configuration-unsent-result` / 双人 unsent-abandon（SQL051）；新鲜 Kong 回读、若随后出现 mutation 则 fail-closed。页面入口随最终发布包开放前，由有 `workflows:approve` 的值班按运维手册调用；不要手工 UPDATE 状态。

**取消排程**：由当前登记的执行人在未领取且页面允许时点击「撤销」，输入 `cancel-schedule` 确认，再核对排程终态。窗口已结束、已领取或结果未知时可能无法撤销；保留原记录并按 [原请求核验](#237-响应中断结果未知与原请求核验) 处理。撤销排程不会回滚已执行步骤，工单和排程状态须分别核对。

**窗口或影响范围冲突**：若登记、激活或执行入口提示冲突，保留原响应，核对原工单、当前排程和真实目标；未显示冲突也不保证其他变更可以并行执行。平台不会因此自动延期或修改已保存窗口，不能换集群别名、切换直接模式或重复点击绕过冲突。先按原请求核验并与相关负责人协调；确需另选窗口时，由值班人员核实原结果并确认允许继续，仍有未核验请求时保持阻断。之后按当前能力撤销尚未领取的旧任务，再从当前配置准备独立新预览、登记新窗口并重新审批。不能编辑旧窗口、续期旧授权或沿用旧票。

工单和排程的执行结果以原回执及实际业务核验为准，通知只用于提醒；接收设置见 [事件与通知](#16-审计事件与通知)。

### 23.10 控制面、身份、监控与实体说明的专项检查

- **集群与数据源**：在「审阅配置变更」核对真正受影响的登记项及地址、执行模式、认证方式。预览只说明认证配置，不显示秘密；保存认证不等于地址已经连通，执行后重新探测。新集群登记仍遵循全局登记权限，不能借“直接执行”影响已受审批保护的集群。
- **工作区**：核对实际目标工作区，归档或恢复按页面要求确认。新工作区会初始化三个内置角色，不会自动绑定用户或团队。工单用于存放记录的工作区不等于授予默认工作区权限；以「影响范围」中的实际目标为准。
- **身份与权限**：审阅用户/团队/角色、权限范围、成员及绑定的前后变化，尤其检查 global、workspace、tag_group 和 entity 范围。执行可能立即改变本人菜单和写入能力；当前角色不能通过工单授予超出自身可委派范围的权限。
- **监控通道**：先由运维登记真实 Prometheus 数据源并准备抓取或 collector 凭证。在「Vitals 监控 → 配置监控通道」选择「原生 Prometheus · 服务 / 路由」或「日志采集通道 · Consumer 近似指标」，确认集群名称并审阅全局插件及平台设置。执行后等待配置传播与真实采样；连通、审批或插件成功都不能替代指标核验。
- **实体说明**：在实体详情维护负责人、说明与扩展元数据。审批模式先「预览变更」，在「实体说明变更审批」生成/审阅预览并提交。删除仅让说明进入可恢复状态，不删除活动网关实体；恢复按当前对象权限办理。普通说明中禁止放凭证。

本站是否已开放上述操作，以正式发布记录和当前能力为准。部署和恢复要求见 [部署与运维手册](production-operations-guide.md#19-m11审批政策与实体工单运维)。
