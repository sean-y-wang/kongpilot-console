# KongPilot 平台使用手册

适用范围：当前已实现的 M0–M8 页面与交互，目标网关为 **Kong Gateway OSS 1.5.x**。本手册依据实际前端路由、表单、服务器能力和权限合同编写，不代表 M8 的整体生产验收已经通过。环境上线、部署状态、最终验收结论以对应交付记录为准。

M9 运维工具箱、M10 配置治理中心、M11 完整变更工单与审批编排尚未上线。当前「变更审批」提供 M6 基础审批，并用于已接入的门户、事件和 M8 配置操作；不提供 M11 的多级审批、会签、计划执行时间、变更窗口或完整工单看板。权限定义中出现未来模块名称不表示对应功能已经可用。

本手册面向平台管理员、工作区管理员、网关运维、业务配置人员、只读审阅人员及门户开发者。部署参数、数据库灾备、网络规则、SMTP、身份提供方和流水线秘密配置由运维交付文档说明。

## 1. 开始使用

### 1.1 控制台与开发者门户

控制台和开发者门户是两个站点，两套账号体系。

| 入口 | 使用者 | 主要用途 |
| --- | --- | --- |
| KongPilot | 平台、运维、业务管理员 | 集群与工作区、网关实体、权限、监控、门户管理、审计、通知、配置变更 |
| 独立开发者门户 | API 使用方 | 阅读公开文档、注册开发者、管理自己的应用、申请和领取 API Key |

向平台管理员取得本站点的实际 HTTPS 地址。不要向浏览器输入或开放 Kong Admin API 地址。浏览器的网关管理请求全部经过控制台后端；`http://kong:8001` 是后端登记时的默认内部地址，不是普通用户访问入口。

### 1.2 登录和个人账号

1. 打开控制台，输入「账号」和「密码」，点击「登录控制台」。
2. 若平台配置了 LDAP，可在「账号认证方式」选择实际提供方，再使用相应账号密码。若配置了 OIDC，页面显示提供方的单点登录按钮；没有按钮时不能自行填写任意身份提供方地址。
3. 初始账号被要求修改密码时，先完成「我的账号」中的修改，随后重新登录。密码至少 12 位，包含大小写字母、数字和符号，UTF-8 长度最多 72 字节。
4. 登录后，从右上角用户菜单进入「我的账号」。可修改显示名称、语言和时区；English 当前为预留选项，默认界面为中文。
5. 修改密码会撤销本账号全部会话。忘记密码时联系有权管理员重置，不通过反复尝试密码绕过登录锁定。

「登录会话」列出来源 IP、客户端信息、登录时间、到期时间和当前会话。可以「撤销会话」或「撤销全部会话」，均需确认；撤销当前会话会立即退出。列表不会显示令牌或令牌哈希。认证失败、账号停用、权限撤销或会话到期时，以页面错误和重新登录要求为准。

### 1.3 确认当前管理范围

每次操作前检查顶部的「集群」和「工作区」。集群选项显示名称与环境，例如 `支付网关 · prod`。不同集群具有独立的连接、执行模式、配置和数据源。工作区属于所选集群。

切换集群或工作区会改变列表、详情、统计和当前权限。已经打开的编辑表单若提示「操作范围已切换」，关闭后在新范围重新打开；不要继续提交旧表单。对原操作结果的核验仍使用原集群、原工作区和原操作标识，不能用当前选择替换。

工作区停用时，页面提示「当前工作区已停用，仅可读取网关配置」。恢复网关对象前，应先由有权人员恢复并启用原工作区。工作区的停用或软删除不等于停止 Kong 代理流量。

## 2. 菜单与页面位置

深色侧栏按当前账号的权限显示。菜单缺失或按钮禁用通常表示未授权、范围未就绪、工作区停用、当前状态不允许，或存在待核验操作。输入详情 URL 不会绕过服务器权限。

| 菜单或页面 | 控制台路径 | 内容 |
| --- | --- | --- |
| 总览 | `/` | 连接状态、可用插件、数据源、工作区实体索引统计 |
| 集群管理 | `/clusters` | 登记、编辑、探测、停用集群 |
| 数据源管理 | `/data-sources` | 当前集群的 Prometheus、Loki 连接 |
| 插件中心 | `/plugin-center` | 插件市场、实例、优先级与冲突 |
| 工作区管理 | `/workspaces` | 工作区资料、启停、软删除和恢复 |
| Services | `/entities/services` | 上游服务配置 |
| Routes | `/entities/routes` | 路由匹配与 Service 绑定 |
| Consumers | `/entities/consumers` | 调用方与六类凭证 |
| Plugins | `/entities/plugins` | 插件实例配置与绑定 |
| Upstreams | `/entities/upstreams` | 负载均衡、健康检查和 Targets |
| Certificates | `/entities/certificates` | TLS 证书、私钥与 SNI |
| CA Certificates | `/entities/ca_certificates` | CA 证书 |
| SNIs | `/entities/snis` | SNI 名称与证书关联 |
| 授权子实体 | `/authorized-children` | 仅获子实体权限时查看 Targets 或凭证 |
| 回收站 | `/recycle-bin` | 网关对象归档、恢复与恢复材料销毁 |
| 工作区迁移 | `/workspace-migrations` | 预览并执行有依赖关系的归属迁移 |
| Vitals 监控 | `/vitals` | 实际指标、采样质量与下钻 |
| 开发者门户 | `/portal` | 发布 API、审核开发者、应用、Markdown 与门户设置 |
| 变更审批 | `/workflows` | 当前已接入功能的基础审批和执行记录 |
| 审计日志 | `/audit` | 筛选、详情、导出与审计链验证 |
| 事件中心 | `/events` | 事件钩子、渠道、订阅、投递与重试 |
| 通知中心 | `/notifications` | 本人通知、批量标记与个人订阅偏好 |
| 配置快照 | `/snapshots` | 快照、定时捕获、快照回收站 |
| 导入导出 / Diff | `/configuration` | 导出、上传预检、不可变 Diff、作业结果 |
| GitOps | `/configuration/gitops` | 版本与真实配置作业关联 |
| 身份与权限 | `/access` | 用户、团队、角色、权限矩阵 |
| 我的账号 | `/profile` | 本人资料、密码和会话 |

实体详情路径为 `/entities/:entityType/:entityId`，通常以抽屉打开。M8 详情页为 `/snapshots/:id`、`/configuration/plans/:id`、`/configuration/jobs/:id`；工作流详情为 `/workflows/:id`。移动端点击顶部导航切换按钮展开侧栏。

「运维工具箱」当前是禁用入口，没有可用工具页面。路由匹配调试、通用批量工具、配置草稿、Lint、漂移、Promote 等不得按未来规划当作现有功能使用。

## 3. 列表、筛选和确认规则

### 3.1 服务端分页

网关实体使用 Kong 游标分页，由后端转为控制台游标。典型列表显示「当前页 N 条 · 总数未知」、「上一页」「下一页」和已访问页选择器。只有实际返回下一页游标时才能继续；不能跳到尚未访问的任意页。实体列表可选 10、20、50、100 条；部分管理列表固定每页 20 条。

更换范围、筛选、排序或每页条数后，列表从第一页开始。总数未知不是零条；没有下一页也不表示整个集群为空。插件、门户、通知等有扫描预算的列表可能返回不足一页并提示筛选未完成，此时使用返回的下一页继续。不要把不完整扫描当成「没有对象」。

集群登记列表和数据源列表等少量元数据页面采用其自身分页；不要将这些页面的总数理解成网关实体的实时总数。

### 3.2 搜索和索引

实体列表支持名称或 ID 搜索、tags 过滤以及名称和创建时间排序。「Kong 原生游标顺序」表示使用原生列表顺序；检索排序可来自后端索引。页面会显示「检索索引 · 最近同步」和同步异常。

索引统计与网关详情可能短暂不同。遇到差异，先刷新具体实体，再检查总览的最近索引同步时间。有权限时可以「同步索引」。DB 模式配置传播也存在数秒延迟；「配置生效中」表示已提交且仍须重新读取或发起真实代理请求验证。

### 3.3 二次确认

危险操作和多项管理变更使用输入确认：在「确认名称」输入框中原样输入页面要求的名称或短语。大小写、空格必须一致；未匹配时确认按钮禁用。取消确认框不会提交该操作。

配置计划还单独要求计划名称；有删除时，再输入服务器给出的「删除确认值」。不要只看按钮颜色，先核对目标、范围、删除数量和说明。按钮禁用时，先解决提示条件，不通过修改请求或 URL 强制发送。

## 4. 集群、环境和数据源

### 4.1 登记与探测集群

有登记权限的管理员进入「集群管理」点击「登记集群」，填写：

- 集群名称与环境，如 dev、staging、prod。
- 控制台后端可达的 Admin API 地址。
- 执行模式：直接执行或工单审批。
- 集群标签。
- 连接认证：无认证、Bearer Token、Basic Auth 或自定义请求头。

保存后点击「探测」。集群详情显示版本、最近探测时间、可用插件和能力探测结果。后端读取实际 Kong 版本与能力；版本不是 1.5.x 时会告警并限制网关写入。插件列表来自实际启用清单，不代表规划中的每一种插件在该集群都已安装。

编辑时原连接秘密不回显。「保持原认证」保留原认证；改为其他方式时输入新的完整认证信息。受保护的连接地址可能不显示，留空按页面说明保留原值，不复制掩码作为新地址。

「停用」停用的是控制台登记，Kong 网关继续运行。需输入集群名称确认。环境名称是管理元数据，不会自动迁移配置。

### 4.2 直接执行与审批模式

直接执行仍需要当前权限、工作区、版本及对象校验。审批模式下，只有已接入真实工作流处理器的功能才能提交审批；登记工单、批准和实际执行是不同阶段。

当前原生实体编辑器、部分 Targets 和普通凭证写按钮在审批模式下明确禁用。门户凭证审批、已支持的事件配置和 M8 配置计划通过其实际工作流入口处理。切换执行模式不会自动为所有原生按钮创建完整 M11 工单功能；不要为绕过流程临时改为直接模式。以具体页面提示、服务器返回能力及工作流结果为准。

### 4.3 配置 Prometheus 或 Loki

1. 顶部选择目标集群，进入「数据源管理」。
2. 点击「添加数据源」，填写名称、类型、服务地址、连接认证和「启用连接」。地址应由后端可达。
3. 保存后点击「测试」，检查状态和「最后探测时间」。
4. 在 Vitals 中选择已配置通道核验实际采样。

数据源连通不表示指标已经到达。Prometheus 抓取、日志采集和 Loki 内容须由部署通道配置；测试连接与监控数据质量分别判断。「移除」须确认数据源名称，按页面完成登记的停用或归档，不会停止外部 Prometheus/Loki 服务。

## 5. 工作区与总览

### 5.1 创建和维护工作区

进入「工作区管理」点击「创建工作区」，填写代码、名称、负责人用户 ID 和说明。代码以小写字母开头，后续使用小写字母、数字、下划线或连字符；创建后代码不可编辑。负责人从授权用户列表选择，也可点击「设为我」。

工作区支持启用、停用、编辑、软删除与原 ID 恢复。默认工作区受到保护，不能按普通工作区删除。删除不提供物理删除工作区接口。「工作区回收站」恢复元数据后，必要时再启用，再恢复其网关归档。

### 5.2 软隔离的边界

Kong 1.5 OSS 没有原生 Workspaces。控制台维护工作区元数据，并用保留归属标签管理实体；默认工作区收容没有归属标签的历史实体。普通业务标签可使用 `team:pay` 等逻辑值。

不要手工填写、删除或伪造 `workspace:` 和 `kos-ws-` 保留标签。Targets 归属继承 Upstream，凭证归属继承 Consumer，历史子对象标签不改变有效归属。全局绑定插件仍在整个网关运行，工作区标签只限制管理可见范围。

直连 Admin API 可以绕过控制台软隔离与审计，因此需要网络隔离。无效、多重或指向已删除工作区的归属会导致对象被隔离出正常工作区列表和统计；平台管理员应核验，不意味着代理配置已自动删除。

### 5.3 跨工作区迁移

1. 选择源工作区，进入「工作区迁移」。
2. 选择同一集群中已启用的目标工作区。
3. 加入 1–50 个根对象；迁移 Target 或凭证时，选择真实父 Upstream/Consumer 和凭证类型。
4. 点击「预览迁移差异」，查看前后标签、依赖、共享引用、冲突、计划期限和读取预算。
5. 无阻止项且具有当前权限时，按提示确认目标名称，执行迁移。
6. 查看逐对象状态；部分完成或结果待核验时，先读取原回执并核验迁移状态，不能另建计划重发已完成步骤。

共享引用不会自动变成可写对象，跨区迁移也不授予目标区权限。需要跨集群环境发布时，当前不提供 M10 Promote 向导。

### 5.4 总览的含义

总览显示登记集群、最近连接状态、当前集群可用插件、数据源和工作区配置概况。工作区实体数来自分批更新的检索索引，有最近同步时间；网关当前配置以详情重新读取为准。流量数据通道未启用时会明确显示不可用，不生成虚构流量。

## 6. 核心网关实体管理

### 6.1 通用创建与详情

1. 选对集群和工作区，打开对应实体菜单。
2. 点击「创建 Services」「创建 Routes」等实际按钮。
3. 按当前 Kong schema 表单填写必填项。枚举、默认值、条件说明和嵌套字段由实际 schema 决定；不支持的字段不要通过额外 JSON 强塞。
4. 点击「保存配置」，阅读错误的字段路径和可读校验说明。
5. 回到列表打开对象，检查 `Configuration`、实际关系标签页与 ID，再核验代理行为。

详情中的 Service、Route、Consumer、Certificate 等关系可点击跳转。只有服务器实际返回且当前账号可读的关系才出现。说明/负责人等控制台注释与 Kong 原生字段分别保存；不能把任意 description 字段加到 Kong 不支持的实体。

### 6.2 八类实体速查

| 实体 | 主要配置 | 常用核验 |
| --- | --- | --- |
| Service | protocol、host、port、path、retries、连接/读/写超时、客户端证书引用 client_certificate、tags | 目标地址和超时，关联 Routes、Plugins，客户端证书引用是否正确 |
| Route | Service、protocols、methods、hosts、paths、headers、SNI、来源/目的地址、strip_path、preserve_host、regex_priority、HTTPS 重定向和 path_handling | 请求范围是否被扩大；关联 Service；协议和路径处理；1.5 不支持表达式路由 |
| Consumer | username、custom_id、tags | 业务身份、关联插件和六类认证凭证 |
| Plugin | 名称、协议、启停、Service/Route/Consumer 绑定、动态 config | 绑定对象、同名选择优先级、实际插件链 |
| Upstream | 实际 schema 提供的 algorithm、slots、哈希来源/回退/cookie、主动/被动 healthchecks | Targets 权重、健康状态、Service.host 是否使用正确 Upstream 名称 |
| Certificate | PEM cert、key、tags 和 SNI | 到期时间、Subject、Issuer、Fingerprint、证书与私钥匹配 |
| CA Certificate | 独立 CA 对象的 PEM cert 和 schema 允许的 tags | 核对 CA 证书内容及实际 schema；Kong 1.5.1 Service 不提供 CA 引用字段 |
| SNI | name、certificate、tags | TLS 名称与目标 Certificate 绑定 |

算法和字段选项以当前 1.5 schema 为准，不把其他版本的字段当作本集群能力。Kong 1.5.1 Service 不支持 `tls_verify`、`tls_verify_depth`、`ca_certificates`，客户端证书引用使用 `client_certificate`；参见 [Kong 1.5 兼容性契约](../kong-1.5-compatibility.md)。表单支持开关、数字、文本、数组增删、record、map、枚举及嵌套数组记录。

### 6.3 Route 请求头与秘密字段

原秘密字段通常显示掩码，编辑时留空保留原秘密；不得将掩码填写成新值。Route 含隐藏请求头匹配时，改其他字段会保留隐藏条件。若确需全部移除，使用「清空全部请求头匹配」，确认后暂存清空意图，再「保存配置」提交。该操作可能扩大路由匹配范围，并要求对应秘密查看权限。

### 6.4 Upstream Targets 与健康

从 Upstream 详情进入「Targets & Health」。可以添加 Target、编辑目标地址和权重、查看实时健康、手动标为「健康」或「不健康」、软删除。健康状态每 15 秒刷新，也可手动刷新。

目标地址填写 `host:port`，IPv6 采用页面示例格式。Kong 1.5 Target 权重修改会生成新的有效历史行，实际有效 ID 可能变化；以最新返回结果与回执映射为准，不认定原 ID 仍是当前有效 Target。配置导入/回滚路径上，完整封存的权重追加可签发耐久配置工单，并按批准→执行→只读回读核验新物理 ID 与权重；业务排程对完整封存的 configuration_v2 Target 追加可登记，不完整封存仍拒绝；lab 自然 claim 已见，自然 execute 仍可能 `KONG_EXECUTION_CALL_LIMIT`。主动/被动检查未产生有效采样时可能显示未取得状态；手动健康设置也可能因网关状态尚未就绪被拒绝，不能把拒绝包装为成功。

### 6.5 Consumer 六类凭证

从 Consumer 详情进入「认证凭证」，选择 `key-auth`、`basic-auth`、`jwt`、`oauth2`、`hmac-auth` 或 `acls` 标签页。凭证继承 Consumer 归属，但查看秘密仍需要独立权限。

创建凭证不会自动启用对应认证插件。先确认实际 Service、Route 或全局范围上的认证配置，再创建凭证并核验代理请求。普通凭证表单提供「本次保存后授权显示凭证秘密」时，仅有权账号可勾选；临时面板关闭后清除。不要截图包含秘密的面板。

Basic-auth 历史 password hash 不等于原密码，不能直接用于登录或恢复。JWT 的算法和密钥必须匹配。OAuth2 此处管理客户端配置，不表示可以恢复历史 token/session。ACL 分组也需要认证身份与对应 acl 插件实际生效。

若账号只获少量 Target/凭证的实体白名单权限，而不能浏览父实体列表，使用「授权子实体」查看允许的对象、脱敏配置和实际可用操作。该入口不会扩大为整父对象权限。

### 6.6 证书上传和 SNI

PEM 字段支持粘贴，也可「从本地文件读取」`.pem`、`.crt`、`.cer`、`.key`、`.pub`。Certificate 私钥留空按编辑说明保留原值。保存后在详情核验到期提示与私钥匹配状态；「未验证」不能理解为匹配。

绑定 SNI 可以从证书关系或 SNIs 页面完成。修改 TLS 前核对 SNI 名称和目标证书；需要上游客户端证书时，核对 Service 的 `client_certificate` 引用。CA 对象独立管理，不把它作为 Kong 1.5.1 Service 的 CA 配置；完成后通过实际 HTTPS 请求核验。

### 6.7 删除与批量删除

单个实体「删除」及当前页所选实体的批量删除均需确认。删除先保存加密完整对象图到回收站，再由执行器处理实际网关移除；不是只在列表中隐藏原生对象。批量结果逐对象展示，某项成功不等于整批成功。

当前核心列表的批量删除只是已实现能力，不能替代 M9 尚未上线的通用批量打标签、启停、草稿和工具链。审批模式或权限不足时相应按钮禁用。

## 7. 插件中心

「插件市场」显示当前集群实际可用插件、分类、实例索引统计、支持绑定范围和 handler Priority。可以搜索插件名称、按分类筛选、点击「配置 插件名」或「查看实例」。插件未安装或未列入启用清单时不能凭规划名称直接配置；企业专有插件不是本系统的默认 OSS 能力。

「插件实例」支持插件名、绑定层级和 tags 筛选。编辑表单根据 Kong 1.5 的真实旧式插件 schema 动态生成，包含 required/default/嵌套记录/数组/条件说明。保存错误按具体字段修正；不得从别的版本复制不兼容 config。

四种基础绑定为全局、Service、Route、Consumer，可以按插件实际约束组合。同名插件按请求上下文从高到低选择一份已启用配置：

`Consumer + Route + Service → Consumer + Route → Consumer + Service → Route + Service → Consumer → Route → Service → 全局`

已停用的高层实例会回退到下一份适用的启用配置。不同名称插件的执行顺序则由 handler Priority 决定，这与同名实例选择规则分别判断。

在「优先级与冲突」的「请求上下文核验」选择实际 Route、Service 或 Consumer，点击「核验上下文」，查看适用配置、被覆盖实例和当前工作区可见执行链。其他工作区的全局插件、扫描预算或读取失败可能使结果不完整，页面会提示；最后仍需代理请求核验。

全局绑定、脚本插件、file-log 和未知自定义插件等受平台管理员策略保护。全局插件作用于整个网关，即使在某工作区创建也不会获得请求流量隔离。

## 8. 用户、团队、角色与权限

### 8.1 日常管理入口

「身份与权限」包括用户、团队、角色和权限矩阵。按页面的「身份范围」选择全局、当前集群或当前工作区，并按有效、停用、回收记录筛选。

用户账号资料属于全局目录；有工作区用户授权不表示可创建全局账号、改账号资料或重置全局密码。用户的「角色」、团队的「成员 / 角色」用于维护绑定；用户「会话」与「重置密码」需要相应权限。绑定可具有范围和期限，授权者不能超过自身完整授权上限。

内置全局和工作区角色包括 super-admin/admin/read-only 及 workspace-super-admin/workspace-admin/workspace-read-only；受保护内置角色不能直接改写。有权人员可克隆受支持角色再自定义，但 super-admin 不允许按普通克隆流程复制。系统保护最后有效平台管理员，不能以普通停用、删除或解绑流程使管理入口失控。

### 8.2 配置四维权限

在角色行点击「权限」，编辑每条完整授权：

| 维度 | 内容 |
| --- | --- |
| 功能模块 | 如 Services、Routes、门户、监控、快照、审计 |
| 操作 | 读取、写入、删除、审批 |
| 范围类型 | 全局、工作区、业务标签集合、实体白名单 |
| 范围值及约束 | 实际集群、工作区、业务标签或 typed 实体 ID |

工作区范围需明确集群与工作区；tag_group 使用业务标签，如 `team:pay`，对象须命中授权集合，不能把保留工作区标签当业务授权标签。entity 白名单适合少量特例，通过「按名称加入实体」选择真实对象，子对象需选真实父对象。完整一行必须同时匹配，不能把不同角色的模块与范围任意拼接成额外权限。

### 8.3 权限矩阵与继承

选择矩阵角色范围和实际角色，查看「角色 × 模块权限矩阵」。矩阵显示显式授权，具体继承由服务器结合真实对象计算：

- Route 读取权限可给予其 Service 的读取。
- Service 写入/删除按规则级联其 Routes 和绑定 Plugins；Plugin 权限结合真实绑定推导。
- Targets 继承 Upstream，凭证继承 Consumer。
- 秘密查看是独立授权，不能通过普通读取或父子继承推导。

read-only 账号不能写，tag_group 与 entity 授权不会使列表看到其他业务对象。若按钮可见但服务器返回 403，应重新核验当前授权和对象归属，而不是修改 ID 继续尝试。角色修改后权限版本改变，旧查询和迟到结果会失效。

## 9. Vitals 监控

### 9.1 配置与查看

Kong 1.5 OSS 没有原生 Vitals；这里通过 Prometheus 或安全日志采集通道提供自研指标。

1. 先登记并测试数据源。
2. 平台管理员在 Vitals 点击「配置监控通道」，选择实际 Prometheus 数据源及「原生 Prometheus · 服务 / 路由」或「日志采集通道 · Consumer 近似指标」。
3. 输入集群名称确认。抓取凭证和采集器登记由部署工具管理；页面不显示部署秘密。
4. 等待配置传播和采样，查看数据源状态、采样质量及错误码。已部署的 Loki 备选通道可在数据源选择器中切换。

普通查看者可选择工作区聚合；有整个集群监控读取权限时才出现整个集群范围。可选 Service、支持时的 Route 下钻、5 分钟至 7 天范围；页面可每 30 秒自动刷新，也可「刷新监控」。

### 9.2 图表含义与限制

页面提供 QPS、2xx/4xx/5xx 请求率、代理请求/上游/Kong 处理延迟 P50/P95/P99、入站/出站带宽、Service TopN、Consumer TopN 和节点连通状态。

未配置、采样不足、权限不足、不支持或部分数据使用明确状态，而不是补零。切换范围或重新查询时不会沿用旧范围图表。原生 Prometheus 延迟来自直方图插值，Loki 为净化日志的经验分位数，单位毫秒。

Consumer 指标需要日志采集通道，采用至少一次投递语义，可能重复，显示近似请求率。工作区历史指标受归属变更 epoch 与质量规则约束，不应把迁移前流量自动归入现在的工作区。Loki 实际查询时间可能向采样步长内对齐，页面同时显示请求时间与实际评估时间。

登记的 Admin API 地址代表被探测的逻辑节点，不是完整 Kong 节点拓扑。节点指标需要整个集群监控读取权限；Loki 日志通道不提供节点指标。数据源测试绿色不能替代图表采样质量核验。

## 10. 开发者门户与基础审批

### 10.1 管理侧发布门户

在当前工作区「开发者门户」的「门户设置」填写公开门户编码、门户名称、介绍、公开代理地址、品牌标题、主题颜色、欢迎文字及发布/注册开关。只有已发布的门户出现在公开入口。更改编码或公开入口影响该门户全部开发者，应先沟通。

「API 发布」创建 API 名称、编码、授权 Service、说明和分类。API 编码与授权 Service 创建后不可更改。授权边界是 **整个 Service 的全部 Routes**，不是 OpenAPI 文档中单条操作。后端会核验 key-auth、ACL 及托管配置冲突，不能用文档隐藏某个操作冒充网关授权隔离。

上传 OpenAPI 3.x 或 Swagger 2.0 的 JSON/YAML 文档，可用 JSON 安全预览，或在支持的入口由 Service/Route 元数据生成文档。保存文档与发布是独立步骤。阅读器不执行 HTML、脚本、外部引用或试调用。

「Markdown 页面 / 回收站」支持页面编码、标题、Markdown 内容、保存、发布、软归档和恢复。使用普通安全 Markdown；带危险 HTML、脚本等内容会被拒绝，不应期望保存后自动净化任意脚本。恢复归档页面后是草稿，需要再次发布才公开。

### 10.2 开发者审核和应用详情

开发者自行注册后需要管理员审核。管理页可按开发者状态查看资料及实际操作；账户和控制台管理员账户分离。

「应用管理」点击应用名称打开详情，有 `Configuration / 配置`、授权记录、申请/工作流。不同标签页独立核验读取权限；能读配置不表示能读全部授权或申请。授权记录只展示安全元数据，保留旧失效、吊销、预留释放等状态，不显示 API Key。

停用或归档应用前，必须完成已发放授权的吊销；已取消/驳回且从未执行的申请由后台严格核验后释放。恢复应用元数据不会恢复旧凭证。开发者详情展示账号、邮箱、状态、注册时间和资料版本，没有凭证查看入口。

### 10.3 开发者侧操作

门户实际路径包括 `/apis`、`/apis/:id`、`/pages/:slug`、`/login`、`/register`、`/applications`、`/applications/:id`、`/requests`、`/requests/:id`、`/profile`。先选择或通过平台提供的 tenant 入口进入正确门户；不要自行用账号推断其他工作区。

1. 匿名在 API 目录按名称和分类筛选，阅读已发布文档。筛选未完成时点击「继续筛选下一页」。
2. 点击「申请开发者账号」，填写开发者账号、邮箱、显示名称和密码；等待审核。
3. 审核通过后登录门户，在「我的应用」点击「创建应用」，填写名称和说明。
4. 打开所需 API，点击「申请 API Key」，选择自己的活动应用，填写申请说明，提交凭证申请。
5. 在请求记录查看审批和实际执行结果。每个应用 × 发布 API 使用独立凭证，不能跨 API 使用。
6. 执行完整成功后，在应用详情的对应授权卡片查看默认掩码。当前权限允许时点击「查看 API Key」，领取并安全保存。

密钥只在临时面板内存中显示，关闭、页面隐藏或最多 60 秒后清除。这是面板显示期限，不是 Key 有效期。勿截图、把 Key 放入 URL、聊天记录、仓库或工单附件。按发布页面给出的认证位置使用 Key，并通过实际代理地址调用。

### 10.4 基础审批与执行

管理员进入「变更审批」，按状态、「我提交的」或「待我审批」查看工作流。详情显示计划版本、指纹、有效期、差异、影响、快照及每步记录。

有能力时可以「批准变更」「驳回变更」「执行已确认计划」「撤销工单」。驳回需要原因。批准只保存决定；勾选「批准后同步执行」仍要求当前账号有真实执行能力。已批准待执行不表示凭证已创建；部分完成、失败和结果待核验也不表示整条链成功。

读取工作流同时受真实变更对象权限约束。只有 workflows.read/approve 而无门户源对象读取权限的角色，可能无法阅读该门户变更详情；这是权限拒绝，不应新增门户权限只为绕过查看限制。

### 10.5 轮换、停用与吊销

在门户应用详情对应凭证点击「轮换」或「停用 / 吊销」，输入提示的确认短语并提交新的审批申请。提交申请时旧 Key 不会被假标为已失效；只有完整执行后才更新结果。轮换期间新旧凭证可能短暂重叠，按实际执行记录核验。

吊销可选择同时将该授权的 Consumer 与 ACL 移入回收站。完成后旧 Key 失效；恢复访问需要重新申请并批准全新 Key。普通回收站恢复、配置 YAML 导入或快照恢复不能复活门户已吊销的受管旧 Key。

对于少数门户凭证「原生步骤完成但门户元数据未确认」的情况，页面可能按严格能力提供「核验原执行回执」「只提交门户元数据」。它只补元数据，不重新创建凭证。明确首步失败且服务端证明未发放的申请，可能允许「关闭明确失败申请」；失败状态本身不能证明已释放预留。按原 execute 幂等键和服务器资格处理，不新建同内容申请盲目重试。

## 11. 回收站

「回收站」按原集群、归档工作区、对象类型和状态查询。点击归档对象打开完整对象图摘要，查看原 ID、节点、依赖边、共享引用及「查看脱敏 JSON」。私钥和凭证秘密不回显，完整恢复材料在后端加密保存。

1. 删除后确认归档记录和执行状态；部分删除不能当作已完成。
2. 恢复前核对原工作区是否启用、当前权限、依赖冲突与共享引用。
3. 点击「恢复」，按原名称确认。服务端按依赖图生成顺序恢复，Consumer 在绑定插件和凭证之前恢复；不要手工按一个固定错误顺序重建。
4. 检查逐步结果、原/实际有效 ID 和代理行为。Targets 历史有效 ID、Basic 密码及受管门户凭证有额外限制。
5. 不再需要在线恢复材料时，有权人员可「永久删除」，再次确认。它销毁归档恢复材料，历史审计仍保留；不能用它绕过尚未完成的原删除。

工作区、用户/团队/角色、门户页面、事件渠道/订阅和快照各有其元数据回收入口。网关回收站不会自动恢复账号权限、门户 grant 或整套控制台业务数据库。

## 12. 审计、事件和通知

### 12.1 查询和导出审计

「审计日志」默认当前工作区。有完整权限时可选「当前集群完整范围」或「平台全局记录（无集群）」；平台全局不是默认集群。

可按操作人 ID、对象类型/ID、操作、结果、工单 ID、请求 ID、开始/结束时间筛选，点击「应用筛选」。时间输入 UTC ISO，例如 `2026-10-11T08:00:00Z`。无时间筛选时服务端使用其默认有限窗口，不代表全历史。

「详情」展示请求、工单、来源 IP、Before、After 和脱敏 JSON Patch。标为「历史范围未知」的记录不能当作已证明属于当前工作区。请求/登记事件与最终成功事件要分别判断，审计中有记录不表示远端写入完整成功。

导出步骤：选择 NDJSON 或 CSV，点击「创建导出任务」，输入 `导出审计` 确认，等待实际作业结果，检查行数、字节、完整性、原因码和到期时间，能力允许时「下载文件」。文件达到预算或区间不完整时会明确标注，不应作为完整审计台账。审计没有更新、删除按钮。

完整集群/全局权限可使用审计链验证，输入起止序号，查看已检查行数、已验证区间、区间完整性和整体完整性。有下一段时「继续下一段验证」；单段通过不能声称整个历史链已证明完整。

### 12.2 通知渠道和订阅

菜单「事件中心」的页面标题为「事件钩子」。包括事件记录、通知渠道、事件订阅、回收站、投递与重试；需要整个工作区相应权限时才出现渠道和订阅管理。

新增渠道时填写名称、实际可用提供方、完整 HTTPS 目标或邮件收件人，以及提供方支持的认证。Webhook、Slack、飞书、邮件等以当前服务端目录为准；未配置 SMTP 或不可用提供方会禁用。邮件收件人每行一个，最多 50 个；邮件实际 SMTP 由服务器配置。

渠道编辑不回填目标和秘密。若仅改普通状态，保留原目标；更换时勾选「明确更换目标与认证」，输入完整新目标并明确选择无认证或新认证。不能把掩码作为新 endpoint。名称和类型创建后固定，秘密只在当前表单短期内存中。

事件订阅选择当前工作区启用渠道，填写事件类型、可选对象类型/ID和业务标签。事件类型之间 OR，对象 ID 之间 OR，标签之间 AND；三类条件之间 AND。有对象 ID 必须选择类型，ID 必须是真实 UUID。保留工作区标签不能作为业务过滤或权限授权。

事件目录会对「需要观察通道」和「未实现」添加提示，以实际状态为准。证书和健康变化等需要实际观察器产生事件，不能把配置订阅当作已经发生告警。订阅不会授予源对象读取权限。

### 12.3 真实测试、投递和重放

「真实测试」会向当前渠道发送真实固定模板，需输入渠道名称确认。保存配置或审批登记不会自动发送测试。到「投递与重试」检查实际 delivery 状态、尝试次数、HTTP 状态、耗时和安全错误码。

外部投递采用至少一次语义，接收端需容忍重复。排队成功不是投递成功；sending、retrying、uncertain、权限暂停、耗尽等分别展示。未知结果不能假定未送达。

只有当前状态和服务器能力允许时才可「确认重放」，需确认投递 ID，生成独立投递代次。恢复渠道/订阅配置不会自动重放历史投递。不要连续点击重放当作普通刷新。

### 12.4 本人通知与角标

右上角通知铃铛每 30 秒读取当前范围未读数，展开查看最近未读消息和「全部消息」。计数标为「至少 N（扫描未完成）」时是下界；`?` 表示不可用，不是零条。

通知中心可选当前工作区或「本人当前可读消息（跨范围）」，只显示当前账号仍有来源权限的消息。查看详情不会自动标为已读。可「标记已读」「归档」，只改本人标记，不删除事件或改变外部投递。

批量只处理当前页选中的同集群、同工作区 1–100 条通知，使用每条当前版本；确认如 `3 条通知`，任一校验失败整批不修改。跨范围列表不能把不同工作区消息混合批量处理。

「本人订阅偏好」只在工作区范围提供，可配置事件类型、可选对象与业务标签、站内通知开关，并支持偏好软删除与恢复。它不创建外部渠道，不授予其他对象权限。消息来源链接只有当前范围及权限匹配才显示；必要时先选择该消息的原集群/工作区。

## 13. 配置快照、Diff、执行和 GitOps（M8）

本节说明已实现页面的操作合同。M8 最终实际验收仍以交付记录为准，不能从本手册或源码单测推断整条 live 链已经通过。

### 13.1 选择配置范围

M8 列表和表单有「配置范围」：当前工作区、指定 Services 与依赖、完整集群。Service 范围选择 1–100 个当前有权 Service；完整集群仍绑定当前工作区锚点并要求完整权限。换范围后使用「应用列表范围」按服务器重新查询，不在第一页自行筛选伪装成完整范围。

共享引用标为只读，不自动纳入可写范围。快照模块权限不替代原生对象权限；完整部署文件还需实际秘密权限。只得到部分可读配置时可以有安全摘要和不完整提示，但不能称为完整可恢复备份。

### 13.2 手动创建快照

1. 打开「配置快照」的「快照」页，检查列表范围。
2. 点击「手动创建快照」，填写快照名称、说明和配置范围。
3. 点击「捕获配置」，输入快照名称确认。
4. 查看真实捕获作业和状态；仅完成时发布可用版本，不把捕获中、失败或不完整当成 ready。
5. 点击快照名称进入详情，查看对象/页/记录/字节数、完整性、一致性、恢复能力和限制。

快照覆盖原生配置图，包括实际可读的 Services、Routes、Consumers、Plugins、Upstreams/Targets、Certificates、CA、SNIs 及六类凭证，按授权和捕获预算核验。Kong 1.5 不支持跨对象原子快照，外部直连 Admin 的并发变化无法完全排除。

「完整捕获」与「每个凭证可恢复」分开判断。详情展示完整恢复、需秘密输入、需轮换、不可恢复等计数。Basic 原密码不可由旧 hash 推导；OAuth2 客户端恢复不包括旧 token/session。真实可用性仍须代理认证核验。

快照不是 Kong 数据库备份，更不是控制台 RBAC、Portal grant、审计等业务数据的灾备。快照不能授权恢复已退役受管门户旧 Key。

### 13.3 定时捕获

在「定时捕获」点击「新增定时捕获」，填写策略名称、范围、周期、时区、保留天数。周期 5–10080 分钟，保留 1–3650 天。时区用于显示，执行按固定分钟间隔，不提供 cron 或 M11 变更窗口编排。

策略可以编辑、暂停、启用、移入回收站和恢复。恢复策略状态为暂停，需审阅后显式启用。列表展示下次捕获时间与真实状态；不手工推定未发生的定时运行。所有者停用、授权变化或范围变化可能阻止或暂停执行。

定时策略只读取和捕获配置，不自动执行导入、回滚或发布。快照在线保留与独立数据库备份的保留策略分别管理。

### 13.4 比较、归档与恢复元数据

快照详情的「比较快照」选择同实际范围的可读取目标，查看脱敏新增、修改、删除、未变及共享引用。比较明确只读，不授予执行权，也不创建回滚许可。服务端未提供完整 Service roots 时，不查询其他范围假比较。

快照列表「移入回收站」只归档控制台快照元数据，不删除网关对象。「快照回收站」的「恢复元数据」只恢复快照记录，不还原网关。永久销毁须额外确认和服务器能力允许；未决作业、下载引用或回滚基线可能阻止销毁，历史审计保留。

### 13.5 导出和受控下载

从「导入导出 / Diff」的「配置导出」导出当前范围，或从快照详情「从此快照创建导出」。选择：

| 类型 | 用途与限制 |
| --- | --- |
| 脱敏摘要 / review | 配置审阅，不含可部署的完整秘密；不能当作执行备份 |
| 完整 decK YAML（格式 1.1）/ deployment | 包含私钥和凭证，需要完整对象与秘密权限；检查恢复限制，存放到受保护位置 |

确认范围/名称后创建导出作业，查看实际完整性、恢复能力、格式投影提示和状态。作业登记成功不等于文件生成或执行成功。下载必须单独点击「确认并下载文件」，确认服务器给出的名称及秘密保管责任。

下载绑定原 actor、原集群/工作区、原 exportId 与**实际 exportRevision**，使用一次许可，不使用 job.revision 或默认版本 1。缺少实际版本或服务器下载能力时禁止下载。权限、会话或范围变化时取消或忽略迟到文件；浏览器不会把明文文件内容放到查询缓存、路由或日志。

固定格式为 `_format_version: "1.1"`。少量 decK 格式 1.1 不允许的可选 null 字段会在格式投影中省略并报告路径；**YAML merge 的省略不表示清空该字段，原快照回滚仍保留原 null**。秘密备份不直接提交 Git；按组织策略加密或拆分保管。

### 13.6 上传、预检和不可变 Diff

1. 准备受限 decK YAML（格式 1.1），检查目标范围和真实 ID/引用。
2. 在「导入与 Diff」选择范围及 merge 或 sync。
3. 选择文件或在「或临时粘贴 YAML」输入内容。内容只在当前 File/Form 短期内存中，开始上传后清除；未提交时可「清除文件与文本」。不要将内容放入页面 URL、截图或日志。
4. Basic-auth 需要提供可信原密码时，按真实凭证路径设置「替换（可信原文）」；YAML 不含密码时选择保留。历史 hash 不能冒充原文密码。
5. sync 先明确接受完整范围缺失对象拟删除的预检；点击「上传并生成预检 Diff」。上传只预检，不执行网关写入。
6. 打开实际作业后点击「审阅不可变 Diff」，核对计划名称、范围、模式、计划版本/指纹/期限、分类计数、删除数量、共享引用、恢复能力和 blocker。
7. 逐对象点「脱敏字段差异」，查看 add/replace/remove、字段路径、父对象、可用依赖及显式 map 删除。缺失、null、false、0 和空数组各有不同语义；秘密值保持隐藏。

merge 只处理明确新增/修改对象，未出现对象不自动删除。sync 只可在已证明完整的授权范围内拟删除缺失对象；共享引用不会隐式改写。Diff 预览不授予执行权限，当前 before 漂移或权限变化可使计划失效。

### 13.7 执行或提交配置审批

计划详情仅在服务器允许时启用「审阅并执行」或「审阅并提交审批」。打开确认抽屉，原样输入计划名称；有删除时单独输入服务器给出的删除确认值，核对拟删除数量。

提交使用实际 planRevision 和不可变 planHash；元数据 revision 与计划版本不同。执行前重新核验当前授权、before、范围、共享引用及完整回滚基线。删除先完整归档进回收站。

直接模式仍逐对象执行和验证，没有跨对象原子提交。审批模式返回真实工单，在「变更审批」审阅、批准并由有权执行者显式执行；批准或登记不能显示为同步执行成功。按实际能力展示操作，不在浏览器选择任意 CLI driver 或自行发送 Admin API 写入。

### 13.8 作业与逐对象结果

「作业与逐对象结果」及作业详情显示父作业状态、处理进度、审批要求、安全错误码、格式投影、实际原/有效对象 ID、操作和验证状态。某一个步骤成功、排队或审批登记都不表示父作业完整成功。

部分完成或结果待核验时保留原 key 与作业 ID，使用原回执读取，不生成新键重复发送已成功对象。Targets 有效 ID 变化应查看 actual effectiveId；未经完整远端回执和 readback 的步骤不能标为已验证。

审批执行或 HTTP 等待超时后，先按原集群、原工作区和原执行 key 查询父作业、工作流及逐对象 steps。客户端超时不表示零写入；即使最后一步失败或父作业仍显示执行中，前面的步骤也可能已经成功。分别核对每步的原操作标识、远端完成证明、实际对象 ID 和只读回读，保留全部成功与失败结果，不重新发送原 execute，也不换 key 提交同一旧计划。

需要完成剩余目标时，先核验当前配置图和引用关系。由有权人员处理原作业的未决状态，在服务器明确允许后，以**当前图为 before 重新生成独立 Diff**，再审阅变更、恢复能力和删除影响，按集群模式走新的确认与审批。新 Diff 只规划当前仍需完成的变更，不是旧计划的重新执行许可；原成功步骤、回滚基线、审计与失败证据始终保留。

原作业仍运行、仍有未知步骤或当前权限不足时，先停止后续变更并交管理员核验。只读现状匹配不能自动解除 uncertain。没有明确可用的服务器处理能力时，不修改数据库状态，不删除原作业记录。

服务器确认原执行租约已过期、同一原账号/会话和当前权限仍有效时，原作业详情才会显示「确认收口过期执行」。输入 `abandon:原作业ID` 二次确认：**停止重试这一条旧请求，保留已成功对象、原回执及未决事实**。这是零网关写的失败事实记账，不会回滚、重发成功对象或自动重试；返回 uncertain 也不表示网关变更成功。

收口只发送一次。之后从原集群/工作区读取原作业和逐对象结果，以原执行 key、完整执行/计划/租约元组及当前会话和权限核验。完整证明成立后，只解除这一条原作业/原键对应的界面请求阻止；其他未知请求保持阻止，原作业、原审计及 uncertain 事实不会改为 succeeded。后续目标仍须以当前配置图生成独立 Diff，重新审阅并按实际集群模式确认或审批。

若收口响应中断或核验尚未完整，保留收口请求键、原作业 ID 和原执行 key。「核验操作」只读取原作业与 steps，不拿收口的新键查找新作业，不再次发送收口。读取不会自动解除阻止；当服务器已提供完整收口证明且账号仍在原范围时，可通过「确认停止重试原请求」再次输入同一 `abandon:原作业ID`，明确解除对应的一条请求引用。只读账号、错误确认名称、权限/会话/范围变化或不匹配元组都不能提交或解除。

### 13.9 回滚与只读核验

快照详情点击「生成回滚计划」，输入快照名称确认。它捕获当前 before 并生成「当前配置 → 原快照」的新不可变 Diff，不重播旧成功作业。核对完整新增、修改、删除、共享引用与秘密恢复限制，再在计划页进行第二次执行或审批确认。

计划页「只读核验实际结果」观察各对象当前是否存在、期望字段是否匹配、原/实际 ID 与观察时间。后续点击变为「读取原核验回执」。这不会发送原生网关写、不改变原执行状态，也不会解除原 uncertain 阻止；状态匹配只能证明观察时现状，不能证明原操作导致了结果。

恢复后除核对配置与回执，还应验证实际 Service/Route、TLS、Target 权重及各认证类型。缺少原密码、已退役受管凭证等情况须按明确 blocker 处理，不能为了恢复按钮可用临时取消治理边界。

### 13.10 GitOps 的实际使用范围

GitOps 页面记录仓库显示名、commit SHA、流水线引用和当前范围的真实作业 ID。显示名采用英文、数字、空格或 `_ . / -`；SHA 为 40 或 64 位十六进制；流水线引用如 `build/42`，不填 URL、账号、token 或密码。

建议流程：先检查完整导出及恢复能力，授权下载，按组织策略安全存放；受控 CI 上传配置获得不可变 Diff，审阅范围/删除/回滚基线；按直接或审批模式执行；使用原 key 查询作业和逐对象结果；最后「关联版本与作业」记录实际 commit。

关联 commit 不等于已推送、发布或执行成功。控制台不连接 Git、不替用户 push、不执行任意 shell。外部 decK 1.x 使用已授权 BFF 适配会话，不能直连 Kong 8001；流水线认证与秘密由运维配置，不放查询参数。

API 示例只示意业务请求，具体认证、CSRF、原幂等键和执行许可由受控 CI 私有认证层提供：

```text
POST /api/v1/clusters/:clusterId/configuration/exports?workspaceId=:workspaceId
{"scope":"workspace","serviceIds":[],"mode":"deployment","confirmed":true,"confirm_name":":workspaceName"}

GET /api/v1/clusters/:clusterId/configuration/jobs/by-key/:originalKey?workspaceId=:workspaceId

POST /api/v1/clusters/:clusterId/configuration/exports/:exportId/download?workspaceId=:workspaceId
{"revision":":actualExportRevision","confirmed":true,"confirm_name":":serverConfirmationName"}
```

示例中的 `actualExportRevision` 要替换为原作业响应中的真实数字，不使用固定 1。CLI dump/diff 与执行许可分别受限；完整部署通过实际 decK 适配与最终验收记录核验，不凭配置文件扩展名认定兼容或已发布。

## 14. 未知结果、常见问题和安全操作

### 14.1 写入响应中断怎么办

超时、断网或 5xx 不证明操作没有发生。页面会保留原操作引用并显示待核验或阻止重复提交。

1. 停止重复点击提交，关闭危险确认框。
2. 记录原请求 ID、操作/作业 ID、原幂等键、集群、工作区和安全错误码；不要记录 Cookie、秘密或原始 YAML。
3. 使用页面的「核验操作」、原作业/工作流回执或对应只读核验入口。
4. 切换范围后仍按原引用核验；不得新建同内容请求、更换 key 或手工删除记录使按钮解锁。
5. 未证明完整成功、部分完成或远端结果未知时，交由有权人员核验。保留所有已经成功的结果，检查当前配置图；处理原未决状态并得到服务器明确许可后，重新生成独立 Diff，审阅并走审批或该集群的确认流程。不要重播原 execute、换 key 重复旧计划或重复已确认步骤。

「只读核验」是观察，不是自动补写；「恢复元数据」也不是恢复全部网关配置。审计中的 requested/pending 不是终态 succeeded。出现真实远端拒绝时保存错误及结果，不把客户端错误忽略后宣称通过。

### 14.2 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 登录成功却没有预期菜单 | 查看本人权限版本、当前集群/工作区，联系角色管理员核对完整授权；没有总览权限可能直接进入获权模块 |
| 403 或详情打不开 | 核验 source 对象/工作区权限和状态；workflows 权限不自动授予门户或配置读取 |
| 工作区列表缺少对象 | 检查归属、业务 tags 授权、历史迁移和索引时间；由管理员核验异常保留标签 |
| 保存后代理行为暂未变化 | 等待 DB 模式配置传播，重新读详情，再检查实际代理请求；不连续重发 |
| Schema 或插件列表不可用 | 集群探测、版本、后端可达性、插件启用清单；只能用当前 1.5 实际支持字段 |
| 监控为空或显示等待 | 分开检查数据源测试、采集配置、采样量、当前范围/epoch、能力与质量原因码；空不是零流量 |
| API 目录筛选当前页为空 | 若提示未完成，继续游标筛选；核对门户/API是否已发布和分类 |
| 申请已批准却没有 Key | 看是否已显式执行，以及所有原生和门户元数据步骤是否完整；批准不等于发放 |
| 应用不能停用或归档 | 先通过审批吊销活动授权；核验待处理/失败申请预留，不直接恢复或删除旧 Key |
| Target 修改后 ID 变化 | Kong 1.5 历史行语义，按实际 effectiveId 与回执核验 |
| 文件无法下载 | 当前权限、scope/session、artifact真实版本、一次许可、到期/消费状态和服务器能力；不要改 revision 猜值 |
| 导入/回滚被阻止 | 查看 Diff blocker、共享引用、恢复能力、Basic原文、受管Portal边界、before漂移和计划期限 |
| 删除/恢复结果不完整 | 回收站和原操作回执逐对象核验；已完成步骤不可重发，永久销毁不修复未决变更 |
| 事件已排队但接收端没收到 | 查看投递状态和实际尝试；渠道可达性、提供方配置、权限变化和未知发送需分别处理 |
| 未读数是「至少」或 `?` | 下界扫描未完成或当前不可用，不是精确总数或零条 |

### 14.3 秘密和危险按钮

不要复制掩码作为新秘密。凭证临时查看、完整 deployment 文件、TLS 私钥、渠道 Token 和认证密码按组织秘密策略保管；不要放进搜索栏、URL、Git 明文、截图、审计注释或通知模板。

「删除」「移入回收站」「永久删除/销毁」「吊销」「撤销全部会话」「修改密码」「真实测试」「确认重放」「审阅并执行」「确认执行」均有实际影响。先检查说明、确认名称和范围，审核人员与执行人员按授予能力协作。禁用按钮不通过浏览器开发工具绕过。

### 14.4 移动端

移动端支持基础浏览、顶部集群/工作区切换和侧栏折叠。宽表格在表格内部横向滚动；检查固定操作列和完整字段名后再操作。复杂嵌套插件、证书、配置 Diff、大批对象和秘密文件建议使用桌面浏览器审阅，避免只看被截断的名称就确认。

页面 loading 未结束时不要把空表作为已完成或无数据；等待实际行和状态。切换账号、范围或后台标签会清除/忽略迟到秘密面板与下载内容，必要时在当前授权下重新读取。

## 15. 常用操作串联

### 新建一个业务 API

登记或选择正确集群 → 创建并选择工作区 → 创建 Service → 创建绑定 Route → 在插件中心配置认证/安全插件 → 必要时创建 Consumer 和凭证 → 读取实体与插件上下文 → 实际代理请求验证 → 查看 Vitals 与审计。需要开发者自助申请时，再发布 Service 对应的门户 API 和文档。

### 安全移除并恢复一组配置

核对 Service 及 Routes/Plugins/凭证依赖 → 有需要先捕获快照 → 输入名称确认软删除 → 读取完整归档与逐步结果 → 回收站核对原工作区/权限/共享引用 → 按服务器计划恢复 → 检查实际 ID/TLS/代理与认证 → 查原请求审计。不是简单把列表行删除后再贴回 JSON。

### 发布一份配置文件

选当前授权范围 → 上传 merge/sync 预检 → 审阅不可变 Diff、凭证限制和删除数量 → 输入计划/删除确认值 → 直接执行或提交真实基础审批 → 检查父作业与全部逐对象证明 → 实际代理验证 → 登记 GitOps commit/真实 job → 保留原 key 和受保护导出/回滚基线。

### 排查一次变更

获取原请求 ID → 选原集群/工作区 → 审计按请求 ID 筛选 → 看 before/after/diff 和结果阶段 → 打开原作业/工作流 → 核对逐步远端完成与安全错误码 → 对未知仅读取原回执/现状 → 结合 Vitals、事件投递和实际代理验证。没有终态证明时，报告未完成，不写成功结论。

### Kong 1.5 Upstream 算法联动

选择一致性哈希时同时设置 `hash_on`（例如 `header`）及对应的 `hash_on_header`。Kong 1.5.1 的兼容 shorthand 会把 `hash_on=none` 归一化为 `algorithm=round-robin`；仅更改算法而保留 `none`，回显仍是轮询。最少连接算法与哈希来源也有联动，以提交后的实际回显为准。编辑客户端证书绑定时，Service 协议必须是 `https`；HTTP Service 的非空 `client_certificate` 会被 Kong 1.5 校验拒绝。

### 门户发布前的共享集群认证边界

Kong 1.5 的 API Key 归属于 Consumer，凭证本身不限制可调用的 Service。门户发布前会检查整个物理集群的认证图；其他可达 key-auth 路由缺少 ACL 白名单时，新的门户 Key 可能获得额外 API 访问，因此发布会返回 `PORTAL_UNMANAGED_AUTH_BOUNDARY`。为既有业务 Service 配置独立 ACL 组，并把其授权 Consumer 加入对应组后，重新检查认证图、生成并提交新计划。保留原失败工单和回执，勿关闭安全检查或重放原执行。生产验收已实际触发并验证此拒绝。
